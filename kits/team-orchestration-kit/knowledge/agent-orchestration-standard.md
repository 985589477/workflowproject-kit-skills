# Agent 调度标准

## 目的

规定 WorkflowProject 在不同运行环境中的 Skill、父 Agent 和子 Agent 如何协作，避免简单任务被过度拆分，也避免组合任务被单个 Agent 承担到上下文失控。

## 三层职责

| 层级 | 职责 | 是否处理专业产出 |
| --- | --- | --- |
| 父 Agent | 接收需求、检查项目、判断复杂度、建立任务树、创建和回收子 Agent、汇总、验收、向用户汇报 | 不直接替代专业子任务 |
| 子 Agent | 在明确范围内完成一个独立角色或模块任务，返回结构化结果 | 是，仅限任务简报范围 |
| Skill | 提供某一角色或某一工作流的方法、模板和检查标准 | 由当前 Agent 或子 Agent 调用 |

## 强制分流规则

### 简单任务：只调用 Skill

满足以下大部分条件时，任务属于简单任务：

- 只有一个角色或一个工作流。
- 只有一个主要产出。
- 不需要跨角色交接、互审或最终联合验收。
- 不需要多个独立任务并行。
- 不会同时修改多个高耦合模块。

执行规则：

```text
当前 Agent
-> 读取对应 Skill
-> 直接完成任务
-> 按 Skill 的标准验证和汇报
```

禁止为了形式创建子 Agent。输出中必须标明：`执行模式：单 Agent + Skill`。

### 组合任务：创建子 Agent

出现以下任一条件时，任务属于组合任务：

- 至少需要两个角色共同参与。
- 需要产品 -> UI -> 开发 -> 测试等阶段性交接。
- 存在两个或以上可以独立推进的任务。
- 需要不同上下文分别分析、实现或验证。
- 需要多个角色对同一交付物进行验收。
- 用户明确提出团队协作、并行处理或父子 Agent。

执行规则：

```text
父 Agent
-> 读取项目和全局规范
-> 建立任务树
-> 为每个独立任务创建真实子 Agent
-> 子 Agent 读取任务简报并调用对应 Skill
-> 子 Agent 返回结构化结果
-> 父 Agent 汇总、检查交接、继续调度或回退
-> 父 Agent 统一验收并向用户汇报
```

组合任务必须标明：`执行模式：父 Agent + 子 Agent`，并报告每个子 Agent 的编号、职责、状态和结果。

## 子 Agent 边界

- 子 Agent 只能处理父 Agent 分配的目标、文件范围和验收标准。
- 子 Agent 不得擅自改变全局架构、技术栈、模块边界或任务优先级。
- 子 Agent 发现范围外问题时，记录为风险或待确认项，交回父 Agent。
- 共享文件存在写入冲突时，父 Agent 必须重新拆分顺序或指定唯一写入者。
- 子 Agent 不得自行无限创建下一级 Agent；需要继续拆分时，先向父 Agent 请求授权。

## 运行环境门禁

组合任务必须区分“真实子 Agent 调度”和“单 Agent 模拟分阶段执行”：

1. 如果运行环境提供 `spawn_agent`、`subagent` 或等价能力，父 Agent 必须创建真实子 Agent。
2. 如果运行环境没有真实子 Agent 能力，父 Agent 必须明确报告能力缺失，不得声称已经创建子 Agent。
3. 能力缺失时，只有在用户确认后，才可以改用单 Agent 顺序执行作为降级方案。
4. 降级执行必须标明：`执行模式：单 Agent 降级模拟，不是真实子 Agent`。

## 上下文传递规则

父 Agent 不把全部历史对话复制给每个子 Agent，而是传递：

- 项目事实摘要。
- 当前任务简报。
- 必须阅读的文件路径。
- 允许修改的文件范围。
- 已确认决策和不可改变的约束。
- 输出格式和验收标准。

子 Agent 返回摘要、变更、验证、风险和待确认问题。父 Agent 默认读取这些结果，不重新加载无关的完整历史。

## 最低进度输出

父 Agent 必须持续报告：

```text
执行模式：单 Agent + Skill / 父 Agent + 子 Agent / 单 Agent 降级模拟
当前阶段：
当前调度者：
已创建子 Agent：
已完成任务：
进行中任务：
阻塞任务：
验证结果：
下一步：
```
