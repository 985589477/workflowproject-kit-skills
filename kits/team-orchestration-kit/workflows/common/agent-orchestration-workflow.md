# Agent 调度工作流

## 目标

根据任务复杂度决定直接调用 Skill，或由父 Agent 创建子 Agent 协作，控制上下文长度、角色边界和最终验收。

## 第一步：判断任务模式

先输出判断，不要立即创建子 Agent：

| 判断 | 条件 | 执行方式 |
| --- | --- | --- |
| 简单任务 | 单角色、单产出、无交接、无并行、低耦合 | 当前 Agent 直接调用对应 Skill |
| 组合任务 | 多角色、多阶段、多产出、交接、并行或联合验收 | 父 Agent 创建真实子 Agent |
| 能力不足 | 组合任务但运行环境没有子 Agent 工具 | 先告知用户，确认后才降级为单 Agent 顺序执行 |

## 第二步：简单任务路由

```text
识别任务
-> 选择一个最小能力包或 Skill
-> 当前 Agent 读取并执行 Skill
-> 完成最小验证
-> 输出执行模式和结果
```

简单任务不得创建子 Agent。适例：只分析一份 PRD、只生成一份测试用例、只修复一个已定位的小错误、只生成一个独立设计令牌文件。

## 第三步：组合任务路由

```text
父 Agent 读取项目事实
-> 建立任务树和依赖关系
-> 创建产品/UI/开发/测试等子 Agent
-> 每个子 Agent 读取任务简报并调用对应 Skill
-> 等待结果或接收进度
-> 检查交接和共享文件冲突
-> 调度下一批子 Agent
-> 汇总并执行联合验收
```

只有相互独立的任务才并行。存在前后依赖时必须串行，例如 UI 不能在产品范围未确认前开始设计，开发不能在技术方案和模块边界未确认前实现。

## 第四步：子 Agent 任务简报

创建子 Agent 前必须填写：

- 任务编号和父任务编号。
- 角色和目标。
- 输入文件和必须阅读的规则。
- 允许修改的文件范围。
- 禁止自行决定的事项。
- 预期产出。
- 验收标准和返回时间点。

使用 `06-templates/common/agent-task-brief-template.md`。

## 第五步：子 Agent 结果回报

子 Agent 完成后必须返回：

- 状态和完成摘要。
- 修改文件和未修改文件。
- 验证命令及结果。
- 已确认决策。
- 风险、阻塞和待确认问题。
- 对父 Agent 的下一步建议。

使用 `06-templates/common/agent-result-report-template.md`。

## 第六步：父 Agent 汇总和回退

父 Agent 必须判断：

- 子 Agent 是否完成了简报范围。
- 结果是否满足验收标准。
- 是否产生文件冲突。
- 是否需要继续创建下一个子 Agent。
- 是否应回退到产品、UI、开发或测试阶段。

父 Agent 不能只转述“子 Agent 已完成”，必须给出证据和下一步。

## 第七步：运行环境能力不足

如果没有真实子 Agent 工具，输出：

```text
当前任务判定为组合任务。
当前运行环境未提供真实子 Agent 调度能力，因此尚未创建子 Agent。
是否允许改用单 Agent 顺序执行？这属于降级方案，不等同于真实父子 Agent 协作。
```

未经用户确认，不得把降级执行当作正常完成。
