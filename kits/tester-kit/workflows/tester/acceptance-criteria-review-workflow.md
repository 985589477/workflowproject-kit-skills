# 验收标准检查工作流

## 目的

用于检查 PRD、用户故事或开发任务中的验收标准是否可测试、可判断、可追踪。

## 什么时候使用

- 需求准备进入开发或测试前。
- PRD 只有功能描述，没有明确通过条件。
- 用户故事存在“好用、稳定、支持、优化”等模糊表达。
- 测试用例设计前，需要先确认验收口径。

## 执行步骤

1. 提取需求目标、用户路径、业务规则和限制条件。
2. 判断每条验收标准是否可观察、可执行、可判断。
3. 标记缺失的正常路径、异常路径、权限、数据、兼容和性能要求。
4. 将模糊验收标准改写为可测试表达。
5. 输出待产品、设计、开发确认的问题。

## 输出要求

- 验收标准清单。
- 不可测试或模糊项。
- 缺失验收项。
- 可测试改写建议。
- 对测试范围和用例设计的影响。
