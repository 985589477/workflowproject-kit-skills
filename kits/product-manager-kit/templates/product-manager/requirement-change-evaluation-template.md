# 需求变更评估模板

状态: draft
版本: v1
角色: product-manager

## 适用场景

当 PRD、版本规划、路线图或开发排期已经形成后，出现新增需求、范围变化、优先级调整或需求取消时使用。

本模板用于生成：

```text
{目标文档目录}/requirement-change-evaluation.md
```

## 输入变量

```text
{变更请求}
{当前阶段}
{原需求或原范围}
{当前 PRD}
{当前版本规划}
{当前产品路线图}
{当前需求池}
{开发排期}
{设计和测试状态}
{上线节点}
{资源约束}
{待确认问题}
```

## 生成要求

1. 先明确本次变更是什么，以及变更发生在什么阶段。
2. 区分变更原因、变更内容和变更影响。
3. 必须评估范围、时间、资源、风险、依赖、文档和下游协作影响。
4. 不要只给“接受/拒绝”的结论，必须说明理由。
5. 必须指出接受变更后需要同步更新哪些文档或工作流产物。
6. 信息不足时进入待确认问题，不要强行决策。
7. 最终给出接受、暂缓、拒绝、进入后续版本或补充评估的建议。
