# Cursor 使用说明

## 适合 Cursor 的场景

Cursor 更适合在 IDE 内围绕产品文档持续协作，例如：

- 修改当前 PRD。
- 根据需求分析补验收标准。
- 对某个产品文档做局部调整。
- 在开发项目中维护 `docs/` 下的产品材料。

## 推荐接入方式

把以下规则放入 Cursor 项目规则或团队约定文档中：

```text
当用户提出产品想法、需求、PRD、验收标准、版本规划、用户反馈或竞品分析相关任务时，优先检查项目中是否存在 product-manager-kit/。

如果存在，请先参考：
1. product-manager-kit/START-HERE.md
2. product-manager-kit/workflows/product-manager/product-manager-workflow.md

不要直接写 PRD。
先判断当前阶段、任务类型、是否需要需求分析和是否需要用户确认。
PRD 后必须判断是否需要验收标准、功能规划、版本规划或需求池沉淀。
```

## Cursor 中的推荐话术

```text
请按 product-manager-kit 的产品经理总入口处理当前任务。
先判断当前阶段和下一步，不要直接生成最终文档。
如果信息不明确，请先列出待确认问题。
```

## Cursor 使用注意

- Cursor 容易基于当前文件直接改文档，因此要先确认当前文档属于哪个产品阶段。
- 如果当前 PRD 缺少需求分析，应先补需求分析。
- 如果验收标准不清，不要直接交给开发。
- 每次修改后都要说明下一步流转。

## 推荐状态格式

```text
当前阶段：
当前文档角色：
相关产品材料：
计划修改：
是否需要用户确认：
下一步：
```
