# 用户故事生成工作流

## 目的

把 PRD、用户场景、功能规划和功能说明转化为用户视角的故事表达，让设计、开发和测试理解功能背后的用户目标和价值。

本工作流重点解决：

1. 将功能从“系统要做什么”转成“用户为什么需要”。
2. 明确用户角色、用户目标和用户价值。
3. 让每条用户故事能追溯到功能、场景或产品目标。
4. 为验收标准、UI 设计和开发任务拆解提供更好的用户语境。

## 适用场景

适用于产品经理相关用户故事生成任务，包括：

- 已完成 PRD，需要转成用户故事。
- 已有功能清单，需要补充用户价值。
- 准备进入设计、开发或测试前，需要统一用户场景理解。
- 需要为敏捷开发准备用户故事。

如果还没有 PRD 或功能清单，应先使用：

```text
04-workflows/product-manager/prd-generation-workflow.md
04-workflows/product-manager/feature-planning-workflow.md
```

## 输入要求

至少需要以下一种输入：

- 用户场景。
- PRD。
- 功能清单。
- 功能说明。

推荐输入：

```text
{目标文档目录}/prd-user-scenarios.md
{目标文档目录}/feature-list.md
{目标文档目录}/prd.md
{目标文档目录}/feature-spec.md
```

## 执行步骤

### 第 1 步：提取用户角色

- 从需求分析、PRD 或用户场景中提取用户角色。
- 区分主要用户、次要用户和维护者。
- 标记不明确角色。

产出：`{目标文档目录}/user-story-roles.md`

### 第 2 步：提取用户目标

- 从用户场景和产品目标中提取用户希望完成的任务。
- 区分用户目标和系统功能。
- 标记目标对应的功能来源。

产出：`{目标文档目录}/user-goals.md`

### 第 3 步：匹配功能和价值

- 将功能与用户目标匹配。
- 为每个功能补充用户价值。
- 排除没有明确用户价值的功能，或写入待确认。

产出：`{目标文档目录}/story-feature-map.md`

### 第 4 步：生成用户故事

- 按“作为 / 我希望 / 以便”结构生成故事。
- 为每条故事标记对应功能、优先级和来源。
- 保留待确认问题。

产出：`{目标文档目录}/user-stories.md`

### 第 5 步：补充验收提示

- 为每条用户故事补充可继续生成验收标准的提示。
- 不展开成完整验收标准，避免和验收标准工作流重复。

产出：`{目标文档目录}/user-story-acceptance-hints.md`

### 第 6 步：评审用户故事

- 检查故事是否包含角色、目标和价值。
- 检查是否能追溯到功能或场景。
- 检查是否有空泛或系统视角故事。
- 检查是否能被下游承接。

产出：`05-review/user-story-review.md`

## 推荐输出结构

```md
# 用户故事

## 用户角色

## 用户故事总览

| 编号 | 用户故事 | 对应功能 | 优先级 | 来源 |
| --- | --- | --- | --- | --- |

## 用户故事详情

### US-001：{故事标题}

- 作为：{用户角色}
- 我希望：{用户目标}
- 以便：{用户价值}
- 对应功能：
- 使用场景：
- 验收提示：

## 不生成范围

## 待确认问题
```

## 质量标准

- 每条用户故事包含角色、目标和价值。
- 每条用户故事能追溯到功能、场景或产品目标。
- 用户故事从用户视角表达。
- 不把系统任务伪装成用户故事。
- 每条故事有验收提示。
- 能被验收标准、UI 设计和开发任务继续承接。
