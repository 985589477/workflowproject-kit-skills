# PRD 评分表

状态: draft
版本: v1
适用对象: 产品经理 PRD 输出

## 适用场景

用于评审以下文件是否合格：

```text
{目标文档目录}/prd.md
```

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 需求承接 | 是否能追溯到需求分析结果，是否覆盖核心问题、用户和场景。 |
| 范围控制 | 是否明确当前版本做什么、不做什么，是否避免范围膨胀。 |
| 用户场景 | 是否清楚描述目标用户、核心场景和用户路径。 |
| 功能清晰度 | 功能模块、功能说明、系统行为和输入输出是否清楚。 |
| 验收标准 | 是否提供可观察、可验证的验收标准。 |
| 下游可用性 | 是否能被 UI 设计、开发、测试或项目管理继续承接。 |

## 总分判断

```text
26-30 分：可以进入下一阶段。
21-25 分：可以进入下一阶段草稿，但必须保留待确认问题。
16-20 分：需要补充 PRD 信息后再进入下一阶段。
15 分及以下：不建议进入下一阶段，应重新生成或重做需求分析。
```

## 评审输出格式

```md
# PRD 评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入下一阶段

## 后续建议
```

## 不合格信号

- PRD 无法追溯到需求分析。
- 没有版本范围。
- 没有不做范围。
- 功能说明只有标题，没有用户操作或系统行为。
- 没有验收标准。
- 把待确认问题写成确定需求。
- 第一版范围明显膨胀。
