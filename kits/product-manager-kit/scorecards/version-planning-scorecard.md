# 版本规划评分表

状态: draft
版本: v1
适用对象: 产品经理版本规划输出

## 适用场景

用于评审以下文件是否合格：

```text
{目标文档目录}/version-planning.md
```

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 目标清晰 | 是否明确版本规划目标和阶段目标。 |
| 首版聚焦 | v1 是否聚焦最小可用价值，是否避免范围膨胀。 |
| 阶段合理 | v1、v1.1、v2 是否有自然演进关系。 |
| 范围边界 | 每个版本包含和不包含内容是否清楚。 |
| 依赖风险 | 是否识别版本依赖、资源风险和待确认问题。 |
| 下游可用性 | 是否能进入路线图、开发排期或发布计划。 |

## 总分判断

```text
26-30 分：可以进入路线图、开发排期或发布计划。
21-25 分：可以进入下一阶段草稿，但必须补充薄弱项。
16-20 分：需要补充版本目标或范围后再进入下一阶段。
15 分及以下：不建议进入下一阶段，应重新做版本规划。
```

## 评审输出格式

```md
# 版本规划评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入下一阶段

## 后续建议
```

## 不合格信号

- v1 范围过大。
- 版本之间只是功能堆砌。
- 没有不包含内容。
- 没有依赖和风险。
- 无法进入路线图或开发排期。
