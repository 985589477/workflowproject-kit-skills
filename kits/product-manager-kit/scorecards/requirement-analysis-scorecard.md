# 需求分析评分表

状态: draft
版本: v1
适用对象: 产品经理需求分析输出

## 适用场景

用于评审以下文件是否合格：

```text
{目标文档目录}/requirement-analysis.md
```

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 问题清晰度 | 是否明确真正要解决的问题，是否区分表层诉求和底层问题。 |
| 用户与场景 | 是否明确目标用户、使用场景和关键用户动作。 |
| 目标与边界 | 是否明确产品目标、成功标准、做什么和不做什么。 |
| 事实与推断区分 | 是否清楚区分已知事实、AI 推断和待确认信息。 |
| 可追溯性 | 是否保留原始描述、资料来源和关键判断依据。 |
| 下游可用性 | 是否能支持后续 PRD、功能规划或验收标准生成。 |

## 总分判断

```text
26-30 分：可以进入 PRD。
21-25 分：可以进入 PRD 初稿，但必须保留待确认问题。
16-20 分：需要补充输入后再进入 PRD。
15 分及以下：不建议进入 PRD，应重新做需求分析。
```

## 评审输出格式

```md
# 需求分析评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入 PRD

## 后续建议
```

## 不合格信号

- 没有说明核心问题。
- 把解决方案直接当成需求。
- 没有目标用户或使用场景。
- 没有范围边界。
- 把 AI 推断当作事实。
- 没有待确认问题。
- 无法支撑 PRD 或功能规划。
