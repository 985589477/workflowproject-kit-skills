# 功能规划评分表

状态: draft
版本: v1
适用对象: 产品经理功能规划输出

## 适用场景

用于评审以下文件是否合格：

```text
{目标文档目录}/feature-planning.md
```

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 目标一致性 | 功能规划是否围绕版本目标和产品目标展开。 |
| 范围清晰度 | 当前版本包含、不包含和后续版本是否区分清楚。 |
| 优先级合理性 | P0、P1、P2 和暂不做是否有明确依据。 |
| 来源追溯 | 功能是否能追溯到 PRD、用户场景或产品目标。 |
| 依赖与风险 | 是否识别关键依赖、风险和待确认问题。 |
| 下游可用性 | 是否能被 UI 设计、开发拆解或版本规划继续承接。 |

## 总分判断

```text
26-30 分：可以进入 UI 设计、开发拆解或版本规划。
21-25 分：可以进入下一阶段草稿，但必须保留待确认问题。
16-20 分：需要补充规划依据后再进入下一阶段。
15 分及以下：不建议进入下一阶段，应重新做功能规划。
```

## 评审输出格式

```md
# 功能规划评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入下一阶段

## 后续建议
```

## 不合格信号

- 功能规划只是功能罗列。
- 没有版本目标。
- 没有优先级。
- 当前版本和后续版本混在一起。
- 功能来源无法追溯。
- 没有依赖、风险或待确认问题。
