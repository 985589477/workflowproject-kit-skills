# 从这里开始

导出对象：项目治理能力包
导出时间：2026-10-15

## 这个包能做什么

- 检查真实项目是否具备架构、模块、设计规范、任务列表和模块文档。
- 缺少关键材料时，先列出缺口并与用户交互补齐。
- 已有材料时，以真实项目文档为事实来源推进开发。
- 让 AI 在写代码前形成整体规划和任务列表，并逐条执行、逐条验证。
- 让代码、项目文档、测试结果和长期记忆保持同步。

本包不是产品经理、UI、开发或测试角色包，也不替代这些角色的专业能力。

## 什么时候使用这个包

- 新项目准备开始长期开发。
- AI 第一次接手已有项目。
- 项目缺少架构或模块说明。
- 用户希望先检查项目治理基础再开发。
- 需要避免 AI 直接猜测架构或大范围修改代码。

## 一句话启动

```text
请使用 project-governance-kit 检查当前项目的规则、架构、模块、设计规范、任务列表和模块文档。如果缺少关键材料，请先和我确认并补齐；如果材料已经存在，请按项目文档规划并执行开发。
```

## 更短版本

```text
请先做项目治理检查，再决定如何开发：{任务}
```

## 外部自动读取配置

可以在真实项目根目录创建 `AI-WORKFLOW-RULES.md`，写入：

```text
你是当前项目的 AI 项目治理协作器。

涉及新功能、架构、模块、UI、开发、测试或项目接手时，先使用 project-governance-kit。

执行前必须检查：
- 目标平台、主要语言、框架、运行时、构建方式和测试方式
- 项目规则入口和已有规范
- 项目架构和模块地图
- 模块边界和模块文档
- 设计规范、组件状态和设备适配
- 当前任务列表和项目记忆

如果关键材料缺失，先列出缺口、风险和需要用户确认的问题，不要直接大范围写代码。
如果是新项目，必须先通过问询确认技术方案；如果是新模块，先询问是否沿用当前项目技术栈。
材料齐全后，先输出整体规划和任务列表，再按任务逐条实现、逐条验证，并同步必要文档。

角色能力按需调用：
- 需求和验收调用产品能力
- 页面、组件和适配调用 UI 能力
- 架构和代码调用开发能力
- 测试、回归和发布调用测试能力

不得为了形式完整而强制所有角色参与。
```

## 执行顺序

```text
读取项目规则
-> 检查治理材料
-> 判断风险和复杂度
-> 与用户补齐缺口
-> 形成整体规划
-> 生成任务列表
-> 按任务执行和验证
-> 同步文档和记忆
-> 评审并说明下一步
```

## 角色全链路原则

本包不固定调用产品、UI、开发或测试角色。它先检查项目治理基础，再根据缺口和任务风险按需调用专业能力。项目治理检查完成不等于代码开发完成，后续仍需按任务列表执行、验证和同步文档。

## 执行状态格式

```text
治理阶段：{检查 / 补齐 / 规划 / 任务执行 / 验证 / 同步 / 评审}
已读取：{文件}
当前事实：{已确认内容}
治理缺口：{缺失或冲突}
调用能力：{无 / 产品 / UI / 开发 / 测试}
当前任务：{任务编号和目标}
验证方式：{命令或检查}
是否需要确认：{是 / 否}
下一步：{下一阶段}
```

## 外部项目输出目录策略

优先使用用户指定或项目已有的 `docs/`、`documents/`、`工程文档/` 等目录。没有合适目录时，才创建 `docs/`。不要在外部项目创建 WorkflowProject 的 `04-outputs/` 或 `12-projects/`。

## 输出确认格式

```text
任务判断：{新项目启动 / 已有项目接手 / 新功能开发 / 治理补齐}
治理结论：{可直接开发 / 需要补齐 / 需要用户确认}
已读取：{文件}
已检查：{架构 / 模块 / 设计 / 任务 / 文档 / 验证}
调用能力：{无 / 产品 / UI / 开发 / 测试}
输出位置：{项目已有文档目录 / docs/ / 对话}
下一步：{动作}
```

## 长期迭代记忆管理

优先使用项目已有的 `AGENTS.md`、`AI-WORKFLOW-RULES.md`、`docs/project-memory.md` 或 `docs/ai-context.md`。没有时，在已有文档目录中建立 `docs/ai-memory-summary.md`。

## 任务结束标准

- 说明读取了哪些项目事实和规则。
- 说明治理缺口及其处理结果。
- 说明整体规划、任务列表和当前状态。
- 说明验证结果和未覆盖风险。
- 说明同步了哪些项目文档。
- 说明是否需要角色继续接管或用户确认。
