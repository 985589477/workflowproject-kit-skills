# 发布与回滚治理评分表

状态: draft
版本: v1
适用对象: developer-kit 发布与回滚治理报告

## 适用场景

用于评估 AI 对发布前检查、发布步骤、回滚方案和上线后观察的治理判断是否可靠。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 发布范围 | 是否明确发布内容、环境、影响用户、模块、配置、数据和权限风险。 |
| 发布前检查 | 是否检查代码评审、测试验收、构建、文档、配置、依赖和阻塞问题。 |
| 发布步骤 | 是否说明步骤、操作、预期结果和失败处理。 |
| 回滚方案 | 是否说明触发条件、回滚动作、权限、验证方式和无法回滚时的止损方案。 |
| 上线观察 | 是否说明观察窗口、指标、日志、业务路径、用户反馈和异常处理。 |
| 风险控制 | 是否将生产、数据、权限、安全、支付和核心流程作为高风险处理。 |
| 交付判断 | 是否基于检查结果判断建议发布、暂不发布或需人工确认。 |
| 后续复盘 | 是否说明发布异常或问题如何进入复盘沉淀。 |

总分：40 分。

## 总分判断

```text
36-40 分：发布治理充分，可以作为上线依据。
30-35 分：基本可用，但需要补充回滚、观察或阻塞检查。
22-29 分：发布治理不足，不建议上线。
21 分及以下：需要重新制定发布与回滚方案。
```

## 评审输出格式

```md
# 发布与回滚治理评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议发布

## 后续建议
```

## 不合格信号

- 没有发布范围。
- 没有发布前检查证据。
- 没有回滚方案。
- 没有上线后观察。
- 生产发布没有高风险处理。
- 存在阻塞问题却建议发布。
- 没有发布失败后的复盘入口。
