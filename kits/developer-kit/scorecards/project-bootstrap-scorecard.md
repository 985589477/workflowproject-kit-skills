# 新项目启动治理评分表

状态: draft
版本: v1
适用对象: developer-kit 新项目启动治理输出

## 适用场景

用于评估新项目启动治理报告是否合格。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 现状识别 | 是否检查并总结项目已有文件、技术栈、启动方式和规范基础。 |
| 技术方案问询 | 技术栈未明确时，是否通过问询确认平台、语言、框架、运行时、构建和测试方式。 |
| 复杂度判断 | 是否能区分轻量项目、标准项目、多模块项目和高风险项目。 |
| 缺失识别 | 是否明确列出缺失的治理文件和规范。 |
| 补齐建议 | 是否区分必需项、建议项和高级项，且不过度工程化。 |
| AI 协作适配 | 是否覆盖 Codex、Cursor、AGENTS.md 等协作入口。 |
| 安全性 | 是否避免覆盖已有文件，是否列出人工确认点。 |
| 后续可用性 | 是否能支撑后续需求开发、模块治理和质量验证。 |

总分：35 分。

## 总分判断

```text
31-35 分：可以作为新项目启动治理方案使用。
25-30 分：基本可用，但需要补充缺失规范或确认点。
18-24 分：需要重新梳理项目现状和补齐建议。
17 分及以下：不建议使用，容易造成项目治理缺失或过度工程化。
```


## 不合格信号

- 没有检查已有文件。
- 上来就创建固定目录。
- 覆盖已有 README、AGENTS.md 或 Cursor rules。
- 没有区分轻量项目和复杂项目。
- 没有人工确认点。
- 没有说明 Codex / Cursor 如何读取规则。
- 把 WorkflowProject 内部目录结构强加给外部项目。
