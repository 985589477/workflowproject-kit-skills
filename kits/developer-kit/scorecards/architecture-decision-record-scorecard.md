# 架构决策记录评分表

状态: draft
版本: v1
适用对象: developer-kit ADR 文档

## 适用场景

用于评估 ADR 是否清楚记录了架构决策的背景、取舍、影响和复盘条件。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 决策必要性 | 是否说明为什么需要 ADR，而不是记录普通开发细节。 |
| 背景清晰 | 是否说明问题、约束、上下文和不能接受的结果。 |
| 备选方案 | 是否列出当前方案、备选方案和保持现状。 |
| 取舍理由 | 是否说明选择当前方案和放弃其他方案的原因。 |
| 影响范围 | 是否覆盖模块、数据、API、测试、文档、性能、安全和部署。 |
| 风险代价 | 是否说明风险、代价和应对方式。 |
| 状态追踪 | 是否有状态、日期、相关文档和替代关系。 |
| 复盘条件 | 是否说明未来什么情况下需要重新评估。 |

总分：40 分。

## 总分判断

```text
36-40 分：ADR 清晰可追溯，可以作为长期架构记录。
30-35 分：基本可用，但需要补充备选方案、影响或复盘条件。
22-29 分：记录不足，后续难以理解决策原因。
21 分及以下：需要重写 ADR。
```

## 评审输出格式

```md
# ADR 评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议接受该 ADR

## 后续建议
```

## 不合格信号

- 没有说明为什么需要决策。
- 没有备选方案。
- 只写结论，不写取舍。
- 没有影响范围。
- 没有风险和代价。
- 没有复盘条件。
- 把普通开发日志当成 ADR。
