# 影响范围分析评分表

状态: draft
版本: v1
适用对象: developer-kit 影响范围分析报告

## 适用场景

用于评估 AI 在实现前输出的文件级、接口级、测试级和文档级影响清单是否可靠。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 变更边界 | 是否明确要做什么、不做什么、成功标准、禁止修改范围和不确定点。 |
| 文件影响 | 是否区分确定影响、可能影响、无需修改，并尽量给出具体文件路径。 |
| 调用链 | 是否说明入口、调用模块、数据状态、输出和异常处理。 |
| 接口影响 | 是否识别接口、服务、参数、返回和协作影响。 |
| 数据状态 | 是否识别数据、状态、归属模块和修改方式。 |
| 测试影响 | 是否说明需要新增、修改、回归或手动验收的测试。 |
| 文档影响 | 是否说明 README、AGENTS、docs、API、架构和模块文档是否需要同步。 |
| 实现顺序 | 是否给出合理的实现顺序和下一步工作流。 |

总分：40 分。

## 总分判断

```text
36-40 分：影响范围清楚，可以进入实现。
30-35 分：基本可用，但需要补充文件、测试或文档影响。
22-29 分：影响范围不清，不建议直接实现。
21 分及以下：需要重新分析影响范围。
```

## 评审输出格式

```md
# 影响范围分析评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入实现

## 后续建议
```

## 不合格信号

- 没有具体文件路径。
- 没有区分确定影响和可能影响。
- 没有无需修改区域。
- 没有调用链。
- 没有测试影响。
- 没有文档影响。
- 没有待确认问题。
- 把局部需求扩大成全项目重构。
