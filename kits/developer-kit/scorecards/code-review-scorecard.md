# 代码评审评分表

状态: draft
版本: v1
适用对象: developer-kit 代码评审报告

## 适用场景

用于评估 AI 对一次代码变更的评审是否可靠，是否能发现影响交付的关键问题。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 问题优先 | 是否先列问题，并按严重程度排序。 |
| 范围检查 | 是否检查改动是否超出影响范围、触碰禁止区域或遗漏文件。 |
| 需求符合度 | 是否检查需求目标、验收标准、不做范围和异常流程。 |
| 正确性 | 是否检查逻辑、边界条件、错误处理、空值、异常和并发等问题。 |
| 模块边界 | 是否检查模块职责、依赖方向、数据和状态归属。 |
| 风险控制 | 是否检查风险评估策略、确认记录和未说明风险。 |
| 测试文档 | 是否检查测试覆盖、未验证内容和文档一致性。 |
| 最小必要变更 | 是否检查过度设计、不必要依赖、不必要抽象和可删除代码。 |
| 交付判断 | 是否基于问题和验证结果给出交付结论。 |

总分：45 分。

## 总分判断

```text
41-45 分：评审充分，可以作为交付判断依据。
34-40 分：基本可用，但需要补充问题定位、测试或文档检查。
25-33 分：评审不足，可能遗漏关键风险。
24 分及以下：需要重新评审。
```

## 评审输出格式

```md
# 代码评审质量评估

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否认可该评审结论

## 后续建议
```

## 不合格信号

- 只总结变更，没有找问题。
- 问题没有严重程度。
- 没有文件路径或影响说明。
- 把个人风格偏好当成阻塞。
- 没有检查测试和文档。
- 没有检查过度设计、不必要依赖或可删除代码。
- 没有交付判断。
- 验证失败仍建议交付。
