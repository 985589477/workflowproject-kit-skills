# Cursor 使用说明

## 适合 Cursor 的场景

Cursor 更适合 IDE 内持续协作，例如：

- 基于当前文件进行局部修改。
- 根据项目规则补全代码。
- 结合上下文理解模块职责。
- 在开发过程中持续检查边界和风险。

## 推荐接入方式

把以下规则放入 Cursor 项目规则或团队约定文档中：

```text
当用户提出开发任务时，优先检查项目中是否存在 developer-kit/。

如果存在，请先参考：
1. developer-kit/START-HERE.md
2. developer-kit/workflows/developer/developer-kit-workflow.md

不要直接进入代码实现。
先判断当前阶段、任务类型、风险等级和是否需要整体功能规划。
实现前必须说明影响模块、实现顺序、验证方式和待确认问题。
```

## Cursor 中的推荐话术

```text
请按 developer-kit 的开发治理总入口处理当前任务。
先判断当前阶段和风险，不要直接改代码。
如果需要实现，请先给出整体功能规划。
```

## Cursor 使用注意

- Cursor 很容易根据当前文件直接改代码，因此更要强调模块边界。
- 如果当前文件上下文不足，应先让 Cursor 阅读相关模块，而不是直接生成。
- 如果涉及多模块改动，应先输出规划，再分步骤改。
- 每次修改后都要要求 Cursor 说明验证方式。

## 推荐状态格式

```text
当前阶段：
当前文件角色：
相关模块：
计划修改：
风险等级：
是否需要用户确认：
下一步：
```

## 不建议的用法

- 不要只选中一个文件就让 Cursor 猜完整架构。
- 不要让 Cursor 在未理解模块边界时大范围改动。
- 不要把验证留空。
- 不要让 Cursor 自动扩大需求范围。
