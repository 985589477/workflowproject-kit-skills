# 影响范围分析工作流

## 目的

在进入代码实现前，帮助 AI 把变更影响拆成具体的文件、模块、接口、数据、测试和文档清单。

本工作流重点解决：

1. 本次变更可能影响哪些文件。
2. 哪些模块、调用链、接口和数据会受到影响。
3. 哪些测试需要新增或回归。
4. 哪些文档需要同步。
5. 哪些区域不能动或需要谨慎修改。
6. 实现前是否仍有不确定点。

一句话：

```text
影响范围分析 = 在写代码前，把“可能会动哪里”说清楚。
```

## 适用场景

适用于：

- 风险评估后，需要进一步明确改动范围。
- 需求会影响多个文件或模块。
- 准备进入代码实现，但还不确定具体文件。
- 需要给用户一个实现前清单。
- 需要明确测试、文档和回归范围。

不适用于：

- 需求还没澄清，应先使用 `requirement-to-architecture-workflow.md`。
- 模块边界还不清，应先使用 `module-boundary-analysis-workflow.md`。
- 变更风险还没判断，应先使用 `change-risk-assessment-workflow.md`。

## 输入要求

至少需要：

- 变更目标。
- 项目理解或相关模块说明。

建议同时提供：

- 架构影响分析报告。
- 模块边界分析报告。
- 变更风险评估报告。
- 相关文件路径。
- 现有测试命令。
- 用户指定的禁止修改范围。

## 执行原则

### 1. 先找证据，再列清单

影响文件应尽量来自实际文件路径、模块引用、路由、配置或测试结构，不凭空编造。

### 2. 区分确定影响和可能影响

输出必须区分：

```text
确定会影响
可能会影响
需要进一步确认
明确不影响
```

### 3. 改动范围优先收敛

优先选择最小可行改动范围，避免把局部需求扩大成全项目改造。

### 4. 测试和文档同步必须进入清单

代码影响范围不只包括源码，还包括测试、配置、文档和构建验证。

### 5. 不确定点不能被隐藏

如果无法确定某个文件、接口或模块是否受影响，应明确标记为待确认。

## 执行步骤

### 第 1 步：确认变更目标和边界

明确：

```text
要实现什么
不做什么
成功标准
风险等级
用户禁止修改范围
```

产出：变更边界摘要。

### 第 2 步：定位候选文件

按类别查找候选文件：

- 页面或路由文件。
- 组件文件。
- 业务逻辑文件。
- API 或服务文件。
- 数据模型文件。
- 状态管理文件。
- 配置文件。
- 测试文件。
- 文档文件。

产出：候选文件清单。

### 第 3 步：分析调用链

梳理：

- 入口在哪里。
- 调用哪些模块。
- 数据从哪里来。
- 状态在哪里变化。
- 输出在哪里呈现。
- 错误在哪里处理。

产出：调用链分析。

### 第 4 步：判断影响类型

对每个候选对象判断：

```text
新增
修改
删除
重命名
迁移
只读确认
无需改动
```

产出：影响类型清单。

### 第 5 步：识别测试影响

判断需要：

- 新增单元测试。
- 修改单元测试。
- 新增集成测试。
- 修改端到端测试。
- 手动验收。
- 回归测试。
- 构建验证。

产出：测试影响清单。

### 第 6 步：识别文档影响

判断需要同步：

- README。
- AGENTS。
- docs。
- API 文档。
- 架构文档。
- 模块边界文档。
- 变更说明。

产出：文档影响清单。

### 第 7 步：输出实现前影响范围报告

报告必须包含：

```text
变更边界
确定影响文件
可能影响文件
无需修改区域
调用链
接口影响
数据和状态影响
测试影响
文档影响
待确认问题
建议实现顺序
```

## 推荐输出结构

```md
# 影响范围分析报告

## 变更边界

## 确定影响文件

| 文件 | 影响类型 | 原因 | 建议动作 |
| --- | --- | --- | --- |

## 可能影响文件

| 文件 | 不确定原因 | 需要确认什么 |
| --- | --- | --- |

## 无需修改区域

## 调用链分析

## 接口影响

## 数据与状态影响

## 测试影响

| 测试类型 | 文件或命令 | 建议动作 |
| --- | --- | --- |

## 文档影响

## 待确认问题

## 建议实现顺序

## 推荐下一步工作流
```

## 快速启动话术

```text
请参考 04-workflows/developer/impact-analysis-workflow.md，
基于下面的变更目标，先做影响范围分析。

变更目标：
【粘贴需求或变更说明】

请不要直接改代码，先输出确定影响文件、可能影响文件、无需修改区域、调用链、接口影响、数据状态影响、测试影响、文档影响、待确认问题和建议实现顺序。
```

## 质量要求

- 必须区分确定影响、可能影响、无需修改和待确认。
- 必须尽量给出具体文件路径。
- 必须包含测试影响。
- 必须包含文档影响。
- 必须标出禁止修改或谨慎修改区域。
- 不能把局部需求扩大成全项目重构。
