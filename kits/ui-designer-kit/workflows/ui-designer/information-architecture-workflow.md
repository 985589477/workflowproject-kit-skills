# 信息架构工作流

## 目的

把设计输入整理成页面信息架构，明确页面需要呈现什么、信息优先级是什么、内容之间如何组织。

## 适用场景

- 需要从 PRD 或需求中拆页面内容。
- 页面信息很多，需要确定主次关系。
- 多角色、多状态、多入口导致信息结构混乱。
- 设计前需要先确认页面区块和内容层级。

## 执行步骤

1. 列出用户进入页面时的核心目标。
2. 列出页面必须承载的信息。
3. 区分主任务、辅助任务和次要信息。
4. 设计页面信息区块。
5. 说明每个区块的优先级、展示条件和来源。
6. 标记可合并、可延后、可隐藏的信息。
7. 输出页面信息架构和待确认问题。

## 输出

使用：

```text
06-templates/ui-designer/information-architecture-template.md
```

## 质量检查

使用：

```text
11-evaluations/output-scorecards/information-architecture-scorecard.md
```

## 进入下一阶段条件

满足以下条件后，进入页面结构或组件状态设计：

- 页面核心目标明确。
- 信息优先级明确。
- 页面区块边界明确。
- 需要用户确认的信息已标记。
