# 可访问性与可用性检查工作流

## 目的

用于检查 UI 设计是否易用、可理解、可操作，并覆盖基础可访问性要求。

## 什么时候使用

- UI 方案准备评审或交付。
- 页面包含表单、流程、数据表、复杂筛选、上传、编辑器、支付或关键操作。
- 目标用户包含新手、低视力用户、移动端用户或高频操作用户。
- 需要提高可用性和减少误操作。

## 输入

- UI brief、页面结构、设计稿或交互说明
- 目标用户和核心场景
- 目标端和适配范围
- 平台规范或无障碍要求

## 执行步骤

1. 检查任务路径是否清楚。
2. 检查信息层级、文案、反馈和错误提示是否可理解。
3. 检查可点击区域、焦点顺序、键盘操作、读屏语义和触控尺寸。
4. 检查颜色对比、字号、间距、状态区分和动效风险。
5. 检查移动端、iPad、横屏、分屏、折叠屏和桌面端的可用性。
6. 输出风险、修改建议和验收标准。

## 具体检查门禁

不能只写“按钮太小”或“体验不好”，必须记录：

- 视觉尺寸和实际可操作热区。
- 目标平台单位和适配方式。
- 用户完成任务的步骤数、重复步骤和中断点。
- 点击、提交、加载、成功、失败、取消、重试和恢复反馈。
- 主要、次要和危险操作的视觉层级。
- 字号、字重、对比、间距、密度和组件一致性问题。

## 输出要求

必须说明：

- 可用性问题。
- 可访问性问题。
- 高风险误操作点。
- 移动端和多端可用性风险。
- 修改建议。
- 验收标准。

## 结束标准

设计方案必须能说明：用户是否能看懂、找得到、点得准、操作后有反馈、出错后能恢复。
