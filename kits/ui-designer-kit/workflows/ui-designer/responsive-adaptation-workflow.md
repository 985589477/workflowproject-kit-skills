# 响应式与多端适配工作流

## 目的

为 Web、移动端、iPad、小程序、桌面端或多端产品设计布局适配策略，避免只给一个静态页面结构。

本工作流解决的问题是：同一个功能在不同屏幕尺寸、设备形态和输入方式下，布局结构、信息密度、导航方式和操作位置应该如何变化。

本工作流必须以组件为单位思考适配，而不是只描述页面整体缩放。

## 适用场景

- 用户要求做网页、移动端、iPad 或多端设计。
- 页面需要响应式布局。
- 设计涉及桌面端和移动端差异。
- iPad 是否独立适配不清楚。
- 需要考虑折叠屏、分屏、双屏或类似 iPhoneDuo 的双区域设备。
- 页面包含复杂列表、表格、筛选、详情、编辑器、看板或多栏结构。

## 设备和断点判断

默认按以下层级判断，不强制所有项目都完整覆盖：

| 类型 | 常见范围 | 设计重点 |
| --- | --- | --- |
| 手机小屏 | 320-374px | 单列、关键操作靠下、减少并列信息 |
| 手机常规 | 375-430px | 单列、触控间距、主任务优先 |
| 平板竖屏 | 768-834px | 双栏可能、卡片密度提高、导航可展开 |
| 平板横屏 | 1024-1194px | 双栏/三栏、列表详情并排 |
| 桌面常规 | 1280-1440px | 内容区宽度、侧栏、表格和筛选效率 |
| 桌面宽屏 | 1536px 以上 | 最大内容宽度、避免信息过度拉伸 |

## 特殊设备形态判断

移动端和轻办公设备不只按宽度判断，还要考虑设备形态：

| 设备形态 | 设计重点 | 交接要求 |
| --- | --- | --- |
| 折叠屏外屏 | 宽度接近普通手机但更窄或更高 | 优先单列、减少横向并列、主操作保持可触达 |
| 折叠屏内屏 | 展开后接近平板但比例特殊 | 判断单栏、双栏或列表详情并排，不直接拉伸手机布局 |
| 双屏设备 | 中间可能有铰链或间隔 | 不把关键内容、按钮、输入框放在中缝区域 |
| 分屏模式 | App 只占屏幕一部分 | 设计需要支持窄窗口、半屏、三分之一屏等弹性宽度 |
| 横屏手机 | 高度受限、宽度增加 | 重点处理导航、键盘、底部操作和内容压缩 |
| iPad 分屏 | 可变窗口宽度 | 不能只按完整 iPad 断点设计，需要说明降级到平板窄屏或手机增强布局 |

如果目标用户可能使用折叠屏、分屏或双屏设备，必须输出特殊设备形态适配表。

## 执行步骤

1. 确认目标端和必须适配的设备。
2. 判断是否需要 iPad 单独适配。
3. 判断是否需要折叠屏、分屏或双屏适配。
4. 判断核心页面结构在不同断点下如何变化。
5. 明确导航、主内容、辅助内容和操作区的响应式规则。
6. 明确列表、表格、卡片、详情页、表单在不同端的处理方式。
7. 明确核心组件在不同端和特殊设备形态下的变化，例如表格转卡片、侧栏转抽屉、双屏列表详情分区。
8. 标记哪些信息在小屏隐藏、折叠、改为二级入口或改为分页。
9. 输出断点策略、布局变化、特殊设备形态适配、组件适配矩阵和开发交接说明。

## iPad 判断规则

遇到以下情况，建议单独设计 iPad：

- 页面有列表 + 详情结构。
- 页面有复杂编辑器、看板、数据分析或管理操作。
- 用户可能横屏使用。
- 移动端单列布局会浪费大量空间。
- Web 桌面布局直接缩放会导致触控体验差。

如果只是简单内容浏览、表单提交或轻量操作，可以先采用移动端增强适配。

## 布局模式

常见布局模式：

| 模式 | 适用场景 | 适配说明 |
| --- | --- | --- |
| 单列布局 | 手机、小表单、内容详情 | 信息线性排列，主操作固定底部或跟随内容 |
| 双栏布局 | iPad、桌面列表详情 | 左侧列表或导航，右侧详情 |
| 三栏布局 | 宽屏后台、复杂工作台 | 导航、列表、详情或属性面板 |
| 卡片网格 | 数据概览、素材列表 | 小屏单列，平板双列，桌面多列 |
| 表格布局 | 后台管理、数据对比 | 小屏改卡片或关键字段列表 |
| 分步布局 | 表单、创建流程 | 小屏分步，桌面可展示步骤导航 |

## 组件适配模式

| 组件类型 | 小屏策略 | 平板策略 | 桌面策略 |
| --- | --- | --- | --- |
| 导航 | 底部导航、抽屉、顶部简化 | 侧栏可折叠或顶部导航 | 固定侧栏或顶部导航 |
| 表格 | 卡片化、关键字段优先、详情二级页 | 保留关键列，详情侧栏 | 完整表格、筛选和批量操作 |
| 筛选 | 底部弹层、抽屉、分组折叠 | 侧栏或顶部筛选 | 顶部筛选区或左侧筛选栏 |
| 表单 | 单列、分步、底部提交 | 单列或双列 | 双列或分组表单 |
| 卡片 | 单列 | 双列 | 多列或瀑布式 |
| 详情页 | 线性内容 | 列表 + 详情双栏 | 多栏详情和属性面板 |
| 弹窗 | 全屏页或底部抽屉 | 中等弹窗或侧滑 | 弹窗、侧滑或抽屉 |
| 主操作 | 底部固定或内容尾部 | 右上角或底部固定 | 顶部右侧、工具栏或批量操作区 |

## 折叠屏、分屏和双屏适配规则

遇到折叠屏、分屏或双屏设备时，必须说明：

- 是否识别设备形态，还是仅按窗口宽度降级。
- 展开态是否采用平板布局、双栏布局或独立双区域布局。
- 折叠态是否采用普通手机布局或窄屏布局。
- 分屏模式下最小可用宽度是多少。
- 铰链、中缝或屏幕间隔区域是否需要避让。
- 关键操作、输入框、弹窗、toast、底部操作栏是否避开中缝和安全区域。
- 列表 + 详情、筛选 + 结果、编辑器 + 预览等结构是否可以拆到两个区域。

推荐策略：

| 场景 | 推荐方案 |
| --- | --- |
| 折叠屏外屏 | 使用手机窄屏布局 |
| 折叠屏内屏 | 优先使用平板双栏或卡片网格 |
| 双屏设备 | 左右屏分别承载导航/列表和详情/编辑，避让中缝 |
| 分屏窄窗口 | 降级为手机增强布局 |
| 分屏宽窗口 | 使用平板窄屏布局 |
| 横屏手机 | 保留核心操作，压缩次要内容，避免底部操作遮挡内容 |

## 组件规划输出要求

输出必须包含组件适配矩阵：

```text
组件 -> 小屏形态 -> 平板形态 -> 桌面形态 -> 折叠屏/分屏/双屏形态 -> 状态 -> 开发注意事项
```

如果某个组件只适用于某一端，必须说明替代组件或替代交互。

## 输出

使用：

```text
06-templates/ui-designer/responsive-adaptation-template.md
```

## 质量检查

使用：

```text
11-evaluations/output-scorecards/responsive-adaptation-scorecard.md
```

## 交接要求

输出必须说明：

- 每个目标端的布局结构。
- 关键断点如何变化。
- 哪些内容显示、隐藏、折叠或移动位置。
- iPad 是否单独适配，以及原因。
- 折叠屏、分屏、双屏是否需要适配，以及明确方案。
- 是否需要避让铰链、中缝、安全区域和系统手势区域。
- 核心组件在不同端的形态变化。
- 开发实现时需要注意的容器、最大宽度、安全区域和触控尺寸。
