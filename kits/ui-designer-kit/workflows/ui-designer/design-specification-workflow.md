# 设计规范确认工作流

## 目的

在进入页面结构、组件设计或视觉方向之前，先确认当前项目需要遵守什么样的设计规范。

本工作流解决的问题是：用户说“做一个好看的页面”时，AI 不能直接凭感觉输出设计，而要先明确设计规范来源、目标风格、平台端、组件约束、通用适配规则、视觉边界、设计令牌策略和可接受的默认假设。

## 适用场景

- 用户没有提供设计规范。
- 用户说不清想要什么风格。
- 项目可能已有品牌、组件库、设计系统或页面样式。
- 设计任务涉及 Web、移动端、小程序、iPad 或多端适配。
- 需要在 UI 方案前先建立风格和布局约束。
- 需要输出可交给开发使用的颜色、字体、字号、间距、状态和组件令牌。

## 输入要求

至少需要明确：

- 设计对象：页面、功能、流程、组件或整套产品。
- 使用端：Web、移动端、iPad、小程序、桌面端或多端。
- 用户期望：想要的风格、参考对象或不喜欢的方向。

建议同时提供：

- 品牌色、字体、Logo、视觉资产。
- 现有页面截图。
- 组件库或设计系统。
- 竞品或参考产品。
- 目标用户和业务场景。
- 目标平台的 UI 框架、主题或样式接入方式。

## 设计规范分层

设计规范至少分为 6 层：

| 层级 | 需要确认什么 |
| --- | --- |
| 品牌规范 | Logo、品牌色、字体、图标、插画、影像风格 |
| 视觉规范 | 色彩、字号、间距、圆角、阴影、密度、动效 |
| 组件规范 | 按钮、输入框、卡片、弹窗、导航、表格、列表等 |
| 布局规范 | 栅格、断点、容器宽度、内容密度、左右栏、顶部栏、底部栏 |
| 交互规范 | 点击、悬停、加载、空态、错误、反馈、禁用、权限不足 |
| 适配规范 | Web、移动端、iPad、横竖屏、不同屏幕尺寸和安全区域 |
| 令牌规范 | 平台中立颜色、字体、间距、圆角、阴影、动效、语义和组件令牌 |

## 通用适配规则必须明确

输出设计规范时，不能只写“需要响应式”或“适配移动端”。

必须明确以下规则：

| 规则 | 需要说明什么 |
| --- | --- |
| 断点规则 | 采用哪些断点，哪些断点必须单独设计，哪些可自动适配 |
| 容器规则 | 页面最大宽度、最小宽度、左右留白、内容居中或铺满 |
| 栅格规则 | 列数、间距、卡片宽度、列表密度、是否允许多列 |
| 导航规则 | 顶部导航、侧边栏、底部导航、抽屉、标签页在不同端如何变化 |
| 操作区规则 | 主按钮、批量操作、底部固定操作、浮动操作在不同端的位置 |
| 信息降级规则 | 小屏哪些信息隐藏、折叠、后移、合并或变为二级入口 |
| 表格适配规则 | 小屏是否改卡片、是否保留关键列、是否支持横向滚动 |
| 表单适配规则 | 单列、多列、分步、校验提示、键盘遮挡和提交按钮位置 |
| 安全区域规则 | 刘海屏、底部 Home Indicator、iPad 分屏和浏览器工具栏影响 |

## 组件意识要求

规划页面时必须先识别组件，而不是只描述页面长什么样。

至少要说明：

- 哪些内容应该抽象成组件。
- 哪些组件已有，哪些需要新增。
- 组件是否需要变体，例如尺寸、密度、状态、权限、平台差异。
- 组件状态是否完整，例如默认、悬停、按下、聚焦、加载、空态、错误、成功、禁用。
- 组件在不同端如何变化，例如表格变卡片、侧栏变抽屉、顶部筛选变底部筛选。
- 组件的复用边界，避免每个页面重新设计一套类似结构。

## 执行步骤

1. 识别设计任务属于哪个端。
2. 检查用户是否提供现有设计规范或参考页面。
3. 确认目标平台、UI 框架和主题接入方式。
4. 如果有规范，提取必须遵守的规则和已有令牌。
5. 如果没有规范，询问用户期望的风格和平台，并决定是否建立最小规范。
6. 给出可选默认规范，但必须标记为 AI 推断。
7. 明确本次设计应该采用的布局密度、组件风格和视觉方向。
8. 输出平台中立令牌策略，必要时进入 `design-token-workflow.md`。
9. 输出组件规划初稿，明确组件、变体、状态和复用边界。
10. 输出通用适配规则，明确断点、容器、栅格、导航、操作区和信息降级策略。
11. 判断是否可以进入信息架构、响应式适配或页面结构设计。

## 默认询问问题

如果用户没有提供足够信息，优先问这些问题：

1. 这是 Web、移动端、iPad、小程序，还是多端都要设计？
2. 使用什么 UI 框架、主题系统或样式接入方式？
3. 有没有现有品牌规范、组件库、设计系统或参考页面？
4. 你希望整体风格更偏工具型、营销型、内容型、专业型，还是轻量简洁？
5. 是否需要适配移动端、iPad、横屏或不同屏幕尺寸？
6. 是否需要输出平台中立令牌，还是已有令牌可以沿用？
7. 有没有明确不能使用的颜色、布局或交互方式？

## 默认假设规则

如果用户允许先按默认假设推进：

- 工具型产品默认采用清晰、克制、高信息密度设计。
- 营销页默认采用视觉冲击更强的首屏和明确转化路径。
- 移动端默认优先单列布局、底部操作、触控安全间距。
- Web 管理后台默认优先桌面端信息密度和表格/筛选效率。
- iPad 默认不能简单放大手机布局，需要考虑双栏、卡片密度和横竖屏。
- 组件默认优先复用已有组件；没有组件库时，先定义最小组件集合，不为单个页面创造过多一次性样式。
- Web 到移动端不能只缩放，应根据任务把表格、筛选、侧栏、批量操作转换成适合触控的组件形态。

所有默认假设必须标记为：

```text
AI 推断，待用户确认。
```

## 进入下一阶段条件

满足以下条件后，才能进入页面结构或组件状态设计：

- 已明确设计端。
- 已明确是否存在现有设计规范。
- 已明确用户想要或不想要的视觉方向。
- 已明确是否需要响应式或多端适配。
- 已明确通用适配规则。
- 已明确核心组件、组件变体和组件状态。
- 已明确令牌源文件，以及是否需要平台适配文件。
- 已标记 AI 推断和待确认问题。
