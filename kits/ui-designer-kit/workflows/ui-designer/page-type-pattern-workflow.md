# 页面类型设计模式工作流

## 目的

用于根据页面类型选择合适的信息结构、布局模式、组件组合和交互模式，避免每个页面从零规划。

## 什么时候使用

- 用户只说“做一个页面”，但没有明确页面结构。
- 需要设计首页、列表页、详情页、表单页、配置页、看板页、搜索页、结果页、设置页等常见页面。
- 多页面产品需要统一页面模式。
- 设计方案需要给开发清楚的页面骨架和模块边界。

## 页面类型示例

- 首页/工作台
- 列表页
- 详情页
- 表单页
- 搜索页
- 结果页
- 设置页
- 数据看板
- 编辑器/创作页
- 审批/流程页
- 空状态/引导页

## 执行步骤

1. 识别页面类型和主要用户任务。
2. 选择页面模式：浏览、检索、编辑、配置、决策、创作、协作或监控。
3. 定义页面骨架：导航区、内容区、操作区、辅助区、反馈区。
4. 选择核心组件组合。
5. 定义不同端的页面模式变化。
6. 输出页面模式、适用场景、限制条件和可复用规则。

## 输出要求

必须说明：

- 页面类型判断。
- 页面目标和主任务。
- 推荐页面骨架。
- 核心模块和组件组合。
- 主要操作路径。
- 不同端布局变化。
- 适用边界和不适用场景。
