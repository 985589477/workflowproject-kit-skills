# 设计令牌与平台适配工作流

## 目的

把设计规范转换成平台中立的设计令牌，并根据目标平台输出对应的适配说明或实现文件。

本工作流解决的问题是：设计规范不能只停留在“颜色舒服、层级清晰”等描述，也不能未经确认直接绑定为 CSS。

## 适用场景

- 新项目需要建立设计系统。
- 现有项目没有统一颜色、字体、间距或组件令牌。
- 需要把同一套设计用于 Web、移动端、iPad、桌面端或多端。
- 设计规范准备交给开发实现。
- 组件需要明确可复用的视觉和状态参数。

## 必须先问询

```text
1. 目标平台是什么？
2. 使用什么 UI 框架或渲染技术？
3. 样式、主题或设计令牌如何接入？
4. 是否需要多个平台共用同一套令牌？
5. 是否需要深色模式、系统字体或无障碍适配？
6. 是否已有设计令牌、组件库或主题文件？
```

如果平台未确定，只输出平台中立令牌，不输出 CSS、Swift、Kotlin 或其他平台实现文件。

## 执行步骤

### 第 1 步：检查现有来源

检查品牌规范、设计系统、组件库、主题文件、样式变量和现有页面，区分已确认事实、AI 推断和待确认问题。

### 第 2 步：确定令牌范围

根据产品和组件范围判断需要覆盖：

```text
颜色、字体、字号、字重、行高、间距、圆角、阴影、动效、断点、容器、密度、组件状态
```

不要为了形式完整创建与当前产品无关的令牌。

### 第 3 步：建立原始令牌

记录基础值，例如原始色板、字号阶梯、间距阶梯和圆角阶梯。原始令牌不直接表达业务场景。

### 第 4 步：建立语义令牌

将原始令牌映射到使用场景，例如：

```text
background.canvas
background.surface
text.primary
text.secondary
border.default
status.error
action.primary
```

### 第 5 步：建立组件令牌

对于日历、按钮、表单、导航等复杂组件，补充组件级令牌和状态：

```text
默认、悬停、按下、聚焦、选中、范围选中、加载、空、错误、禁用、权限不足
```

### 第 6 步：输出平台适配

根据确认的平台输出：

- 平台适配说明。
- 令牌映射表。
- 需要时生成 CSS Variables、TypeScript、Swift、Kotlin、Dart 或 WXSS 文件。

平台适配不得改变设计意图；如果平台能力不足或存在视觉差异，必须记录差异和取舍。

## 推荐输出

```text
design-specification.md      设计规则和使用边界
design-tokens.json           平台中立令牌源文件
platform-adaptation.md       平台映射、差异和适配规则
平台实现文件                 已确认平台且用户要求生成时才创建
```

## 进入开发交接条件

- 已确认目标平台和框架。
- 已确认令牌源文件位置。
- 已明确语义令牌和组件令牌。
- 已明确多平台差异和适配规则。
- 已明确深色模式、字体、单位、触控和无障碍处理。
- 已明确开发可以调整的范围和不可自行改变的设计边界。
