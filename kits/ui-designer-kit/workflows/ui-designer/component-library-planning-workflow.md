# 组件库规划工作流

## 目的

用于把页面设计需求拆成可复用组件、组件变体、组件状态和组件治理规则，避免每个页面都临时设计一套。

## 什么时候使用

- 用户需要建设组件库、组件规范或设计系统组件层。
- 一个产品包含多个页面，且存在重复区块、表单、列表、卡片、弹窗或导航。
- UI 方案准备交给开发，需要明确哪些组件复用、哪些组件新增。
- 设计输出里只有页面效果，没有组件拆分和复用边界。

## 输入

- 产品需求、PRD 或页面说明
- 已有设计规范或组件库
- 页面清单、核心流程和目标端
- 竞品或参考界面

## 执行步骤

1. 识别页面中的核心对象、核心操作和重复结构。
2. 拆分基础组件、业务组件、页面级组合组件。
3. 为每个组件定义用途、输入内容、状态、变体和交互反馈。
4. 判断组件来源：复用已有组件、扩展已有组件、还是新增组件。
5. 定义组件在 Web、移动端、iPad、折叠屏、分屏和双屏下的形态变化。
6. 输出组件优先级、建设顺序和开发交接说明。

## 输出要求

必须说明：

- 组件分层：基础组件、业务组件、组合组件。
- 组件清单：名称、用途、出现页面、复用范围。
- 组件变体：尺寸、密度、状态、权限、端差异。
- 组件状态：默认、悬停、按下、选中、禁用、加载、空态、错误。
- 组件适配：小屏、平板、桌面、横屏、折叠屏、分屏、双屏下如何变化。
- 新增组件理由：为什么不能复用已有组件。
- 开发交接：组件 API、数据字段、状态字段和验收关注点。

## 主动询问规则

如果没有现有组件库、目标端、页面范围或视觉规范，需要先询问。

如果用户只想要单页草案，可以先给轻量组件清单，但必须标记哪些内容需要后续组件化。
