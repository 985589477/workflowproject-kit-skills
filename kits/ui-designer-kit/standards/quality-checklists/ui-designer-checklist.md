# UI 设计质量检查清单

## 适用对象

- UI brief
- 页面结构说明
- 组件说明
- 组件库规划
- 交互状态说明
- 可访问性与可用性检查
- 设计交接文档
- 设计到开发实现约束

## 检查项

| 类别 | 检查项 | 是否通过 | 说明 |
| --- | --- | --- | --- |
| 目标 | 是否明确页面目标 |  |  |
| 用户 | 是否明确目标用户和核心场景 |  |  |
| 信息架构 | 是否说明页面信息优先级 |  |  |
| 页面结构 | 是否说明主要区域和内容关系 |  |  |
| 组件 | 是否列出关键组件 |  |  |
| 组件治理 | 是否说明组件来源、复用边界、变体和状态 |  |  |
| 状态 | 是否覆盖默认、加载、空、错误、成功、禁用状态 |  |  |
| 交互 | 是否说明关键操作路径和反馈 |  |  |
| 规范 | 是否检查品牌、平台、组件或设计系统约束 |  |  |
| 页面模式 | 是否判断页面类型并选择合适页面骨架 |  |  |
| 适配 | 是否说明断点、容器、栅格、多端和特殊设备适配 |  |  |
| 可访问性 | 是否检查颜色对比、触控区域、键盘、焦点和读屏语义 |  |  |
| 可用性 | 是否检查任务路径、信息理解、反馈和错误恢复 |  |  |
| 风险 | 是否说明可用性风险和待确认问题 |  |  |
| 开发约束 | 是否说明布局、组件、数据、状态和验收规则 |  |  |
| 交接 | 是否能被产品、开发、测试继续使用 |  |  |

## 结论

```text
可交接 / 补充后交接 / 暂不交接 / 需要用户确认
```
