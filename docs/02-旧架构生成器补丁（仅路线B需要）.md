# 生成器补丁：`tools/export_unified_kit.py`

> ## ⚠️ 这个补丁**只在路线 B 需要**（保留旧仓库 + 保留生成器）
>
> **路线 A（推荐）已不需要它**：`workflowproject-kit/` 已是「无生成器」形态 ——
> kit 就是一个普通目录，直接用符号链接安装。没有生成器，就没有 rmtree 覆盖、
> 没有内联常量、没有双份拷贝漂移。见 `workflowproject-kit/README-OF-THIS-LAYOUT.md`。
>
> **路线 A 顺带证明了「删生成器」的价值**：同样那 3 处安装器改动，在旧架构里要在
> 134 行的 `r'''...'''` 内联字符串里做；在新架构里它只是一个普通 `.py` 文件，
> 我直接改了（已完成，见 `workflowproject-kit/scripts/install_project.py`）。

> **为什么必须改生成器**（路线 B 的前提）：入口 `SKILL.md` 不是文件，是脚本里的**内联常量** `UNIFIED_SKILL`（L26–136）。
> 手写一个 `SKILL.md` 进 `14-exports/workflowproject-kit/` 没用——
> `export()` 第 640 行是 `shutil.rmtree(OUTPUT)`，**每次导出都重建**。

**一共 5 处改动，其中 3 处是删除。** 设计思路：让新目录 `_unified-src/` 整体拷进去，
然后**删掉那两行会覆盖它的写入语句**——比替换 111 行常量省得多，也更可维护。

```python
    kit_root = OUTPUT / "kits"
    kit_root.mkdir(parents=True, exist_ok=True)

```

`copy_tree` 已在同一文件 L631 定义，`shutil` 已导入。**无需其他改动。**

## 改动 5｜安装器默认不再往项目里拷能力包（在 `INSTALLER` 字符串内）

**为什么**：改动 1 的那 5 条符号链接（README 批 1）让 **6 个能力包已经作为 skill 全局注册**。
既然 agent 能从 skill 目录直接加载，**往每个目标项目里再拷一份 `.ai/kits/` 是纯冗余**——
而且是 314 个文件的变更。需求仍在的场景只有一个：**把项目分享给没有装这些 skill 的人**。

**位置 1**：`INSTALLER` 字符串里的 argparse 块（约 L326–331）
```python
    parser.add_argument("--create-project", action="store_true", help="目标目录不存在时创建它")
+   parser.add_argument("--with-kits", action="store_true",
+                       help="把能力包复制进项目 .ai/kits/（默认不复制：能力包已作为 skill 全局注册，"
+                            "项目内不需要副本；仅当要把项目分享给未安装 skill 的人才需要）")
    raise SystemExit(install(parser.parse_args()))
```

**位置 2**：复制循环（约 L244）
```python
-   for name in selected:
+   for name in (selected if args.with_kits else []):
        source = KITS_ROOT / name
        destination = destination_root / name
```

**位置 3**：提示语（约 L235–236），改成条件输出，避免用户以为装好了
```python
-   print("安装能力：" + ", ".join(selected))
+   if args.with_kits:
+       print("安装能力：" + ", ".join(selected))
+   else:
+       print("能力包：跳过复制（已作为 skill 全局注册）。需要随项目携带请加 --with-kits")
```

## 风险与回退

| 风险 | 处理 |
|---|---|
| `copy_tree` 把 `_unified-src/SKILL.md` 拷进去，但你又想同时保留内联版 | 不要两者并存。改动 2 必须和改动 1 一起做，否则内联版覆盖新入口（**静默**） |
| `_unified-src` 少了某个生成文件（README/INSTALL/…） | 不受影响：那些仍由脚本生成，且写入在 `copy_tree` **之后** |
| 忘了重新导出就 `cp` 到 skill 根 | 会拷到旧的生成物。**先导出，再覆盖安装** |

回退：`git checkout tools/export_unified_kit.py && rm -rf 14-exports/_unified-src && python3 tools/export_unified_kit.py`
