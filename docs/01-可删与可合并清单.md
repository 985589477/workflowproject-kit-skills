## B. 同名但内容不同 —— **需人工判断，不能盲删**

**10 组、86 个文件、5,418 行。** 这些**可能是有意的按角色分叉**（例如
`developer-kit/usage-guide.md` 与 `tester-kit/usage-guide.md` 讲的是不同角色的用法）。

**判断标准**（不要凭"看起来像"就删）：

| 若 | 则 |
|---|---|
| 7 份 START-HERE 只是换了个角色名，流程完全一样 | 合并成一份，用角色参数区分 |
| 各角色确实有不同流程 | 保留，但**抽出共同的 80%**，只留差异 |
| `codex-usage.md` / `cursor-usage.md` 7 份是同一份安装说明 | 合并成一份（它们讲的是**工具接入**，与角色无关） |
| `README.md` 19 份（含子目录） | 逐目录看，很多是**目录说明**，这类就本地留着 |

**我的判断边界**：我只读了原 kit 的 **1.1%**，所以我在 B 组**不做删除决定**。
表里给的是分组事实，取舍需要真读之后定。

## E. 如何复现这份分析

```bash
python3 - <<'PY'
import hashlib, pathlib
from collections import defaultdict
K = pathlib.Path.home()/"Library/Application Support/dsh-desktop/harness/skills/workflowproject-kit"
files = [p for p in K.rglob("*.md") if p.is_file()]
by_hash = defaultdict(list)
for p in files:
    by_hash[hashlib.sha256(p.read_bytes()).hexdigest()[:12]].append(p)
for h, v in by_hash.items():
    if len(v) > 1:
        print(len(v), v[0].name, "->", [str(p.parent.relative_to(K)) for p in v])
PY
```
