# 测试与验收评分表

状态: draft
版本: v1
适用对象: developer-kit 测试与验收报告

## 适用场景

用于评估 AI 在代码实现后，是否完成了足够可靠的测试、构建、手动验收和风险说明。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 验证目标 | 是否明确本次验证要证明什么。 |
| 验证计划 | 是否根据风险等级和影响范围选择合适验证方式。 |
| 自动验证 | 是否运行可执行的 lint、typecheck、test、build 等命令。 |
| 手动验收 | 是否给出可复现的手动验收步骤和预期结果。 |
| 回归范围 | 是否说明需要回归检查的关键路径。 |
| 失败处理 | 是否诚实记录失败、原因、修复和是否阻塞交付。 |
| 未验证内容 | 是否明确说明未验证内容、原因和风险。 |
| 交付判断 | 是否基于验证结果给出是否建议交付。 |

总分：40 分。

## 总分判断

```text
36-40 分：验证充分，可以支持交付判断。
30-35 分：基本可用，但需要补充手动验收、回归或未验证说明。
22-29 分：验证不足，不建议交付。
21 分及以下：需要重新制定验证计划。
```

## 评审输出格式

```md
# 测试与验收评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议交付

## 后续建议
```

## 不合格信号

- 只说“已测试”，没有命令或步骤。
- 测试失败却写成通过。
- 无法验证但没有说明原因。
- 没有手动验收步骤。
- 没有回归范围。
- 没有未验证内容。
- 没有交付判断。
