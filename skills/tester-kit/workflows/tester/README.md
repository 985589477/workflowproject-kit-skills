# 测试工程师工作流

## 当前可用工作流

- `tester-workflow.md`：测试工程师总入口工作流。
- `acceptance-criteria-review-workflow.md`：验收标准检查，用于判断需求是否可测试、可判断、可追踪。
- `test-strategy-planning-workflow.md`：测试策略规划，用于确定测试层级、风险优先级、准入准出和测试取舍。
- `test-scope-analysis-workflow.md`：测试范围分析，用于明确范围、非范围、验收标准和风险。
- `test-data-environment-workflow.md`：测试数据与环境准备，用于明确账号、权限、数据、配置和依赖。
- `test-case-design-workflow.md`：测试用例设计，用于输出可执行测试场景和用例。
- `api-integration-test-workflow.md`：接口与集成测试，用于检查接口契约、数据流、错误码和模块协作。
- `compatibility-test-workflow.md`：兼容性测试，用于规划多端、多浏览器、多设备和特殊屏幕测试矩阵。
- `non-functional-risk-test-workflow.md`：非功能风险测试，用于识别性能、稳定性、安全、可用性和数据一致性风险。
- `regression-test-workflow.md`：回归测试范围，用于判断必测、抽测和可跳过范围。
- `exploratory-test-workflow.md`：探索式测试，用于在常规用例外发现高价值风险。
- `automation-test-planning-workflow.md`：自动化测试规划，用于判断哪些测试适合自动化。
- `defect-reproduction-workflow.md`：缺陷复现，用于整理可交给开发的问题复现报告。
- `test-execution-report-workflow.md`：测试执行报告，用于整理阶段测试结果、缺陷状态和发布建议。
- `release-acceptance-workflow.md`：发布验收，用于判断是否可发布。
