# 探索式测试工作流

## 目的

用于在需求和用例之外，基于风险、经验和用户行为探索潜在问题。

## 什么时候使用

- 功能复杂、交互多、边界不清。
- 常规用例已覆盖，但担心遗漏真实用户操作。
- 测试时间有限，需要快速发现高价值问题。

## 执行步骤

1. 明确探索目标和时间盒。
2. 选择探索维度：用户路径、数据边界、权限、异常、设备、网络、并发、可用性。
3. 执行探索并记录观察、操作、结果和疑点。
4. 将发现转成缺陷、用例补充或风险说明。
5. 输出探索式测试记录。

## 输出要求

- 探索目标。
- 时间盒。
- 探索维度。
- 发现的问题。
- 新增用例建议。
- 风险结论。
