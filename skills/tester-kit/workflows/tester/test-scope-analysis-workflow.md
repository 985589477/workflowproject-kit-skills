# 测试范围分析工作流

## 目的

把 PRD、验收标准、开发变更或缺陷反馈整理成测试范围和非范围，明确本次测试应该覆盖什么、不覆盖什么、风险在哪里。

## 适用场景

- PRD 或开发变更准备进入测试。
- 需求范围较大，需要先拆测试范围。
- 用户只给了模糊测试任务。
- 需要判断是否具备设计测试用例的条件。

## 执行步骤

1. 识别测试对象。
2. 提取需求范围和非范围。
3. 提取验收标准。
4. 识别影响模块、数据、权限和端。
5. 判断风险等级。
6. 输出测试范围、非范围、风险和待确认问题。

## 输出

使用：

```text
06-templates/tester/test-scope-analysis-template.md
```

## 质量检查

使用：

```text
11-evaluations/output-scorecards/test-scope-analysis-scorecard.md
```

## 进入下一阶段条件

- 测试对象明确。
- 范围和非范围明确。
- 验收标准或核心预期明确。
- 高风险和待确认问题已标记。
