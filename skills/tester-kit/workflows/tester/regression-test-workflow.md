# 回归测试范围工作流

## 目的

根据开发变更、影响模块、历史风险和发布范围，判断需要回归哪些功能、哪些路径可以抽样、哪些风险需要人工确认。

## 适用场景

- 功能修复或迭代完成后准备回归。
- 开发改动影响多个模块。
- 需要控制测试成本但不能漏掉关键风险。
- 发布前需要说明回归范围。

## 执行步骤

1. 确认本次变更范围。
2. 识别直接影响模块。
3. 识别间接影响路径。
4. 划分必测、抽测、可跳过范围。
5. 标记高风险回归点。
6. 输出回归测试范围和验证建议。

## 输出

使用：

```text
06-templates/tester/regression-test-template.md
```

## 质量检查

使用：

```text
11-evaluations/output-scorecards/regression-test-scorecard.md
```
