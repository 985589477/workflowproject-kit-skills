# 模板：子 Agent 简报（创建前必填）

> 门禁 05 要求。缺任何一项就重写。
> **简报是父 Agent 的责任**：子 Agent 是全新上下文，它只知道你告诉它的东西。

---

```markdown
## 目标
{一句话，可判断完成与否。不要写"研究一下 X"，要写"列出 X 的 N 条调用点并判断哪些是死代码"}

## 项目背景（子 Agent 不知道的部分）
- 项目是什么：{一句话}
- 语言/框架/版本：{...}
- 相关路径：{...}
- 已有约定（若与常规做法不同，必须说明）：{...}

## 可写边界
允许创建/修改（**白名单，其余一律只读**）：
- {路径/目录}

## 只读范围
可以读但不能改：
- {路径/目录}

## 验收标准（我会据此判断你完成没有）
1. {可验证的条目}
2. {可验证的条目}

## 返回格式（必须照此结构）
```markdown
## 结论
- {结论} —— 证据：`{文件}:{行}` 或 `{命令} → {结果}`

## 计数与统计
- {指标}: {数字}（统计方式：{命令}）

## 未验证 / 不确定
- {我推断但没验证的}：{为什么}
```

**硬性要求：**
- 每条结论必须带 `文件:行` 或命令输出作证据。**没有证据的结论会被我打回。**
- **必须包含「未验证 / 不确定」段**，把推断和事实分开。空的也要写"无"。
- **所有计数、百分比、行数必须给出统计命令。** 我会抽样复核，数字是最容易出错的部分。

## 禁止事项
- 不要修改白名单以外的任何文件
- 不要执行会改变数据的命令（不要跑迁移、不要写数据库、不要 `git commit`）
- 不要安装依赖
- 不要"顺手修一下"发现的其他问题 —— 报告给我，我来决定
- {项目特定的禁令}

## 环境（已实测的命令，直接用）
- 解释器：`{绝对路径}`
- 跑测试：`{命令}`
- {其他}

## 已知地雷（别踩）
- {...}
```

---

## 父 Agent 的复核义务（收到报告后，不能省）

```markdown
## 复核记录
- 收到结论 {N} 条，复核 {M} 条
- **数字类断言：{全部复核 / 未复核}**（数字必须全查 —— 最容易夸大且影响最大）
- 发现并修正：{具体列表；若确实没有，写"无"，但要说清查了什么}
- 未复核：{列表 + 原因}
```

> 写"已核对无误"但列不出任何具体查证动作，通常意味着没真复核。
> 实测经验：复核 ~40 条结论抓出了 2 个夸大的数字和 1 个我自己差点犯的错
> （要删一个 128MB 索引，而查询计划器实际在用它）。
