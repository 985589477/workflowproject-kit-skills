# 模板：基线报告（门禁 01 的产出）

> 拷贝到项目 `AGENTS.md` 的「基线」段，或独立成 `docs/BASELINE.md` 并被引用。
> **每一项都必须是你实测填出来的，不是从文档抄的。**

---

```markdown
# 基线报告 —— {项目名} @ {commit sha}（{日期}）

## 1. 回退点

- 当前 commit：`{sha}`
- 分支状态：{干净 / 有未提交改动（列出）}
- **回退命令（已实测）**：
  ```bash
  {实测过的命令，例如 git reset --hard {sha}}
  ```
- 数据回退：{备份路径 + 恢复命令}

## 2. 测试基线

| 项 | 值 |
|---|---|
| 命令 | `{实测命令，含解释器绝对路径}` |
| 结果 | **{N} passed, {M} failed** |
| 耗时 | {t} 秒 |
| 已知红灯（改前就存在） | {列表 / 无} |

> ⚠️ 数字必须是**我跑出来的**。改完后对比这个数字：**变了就是行为变了**，必须解释原因。

## 3. 类型 / 静态检查门禁

| 项 | 值 |
|---|---|
| 类型检查命令 | `{命令}` |
| 结果 | **{0 错误 / N 错误}** |
| 是否被构建命令覆盖 | {是 / **否**（很多构建命令不做类型检查）} |
| lint 命令 | `{命令 / 无}` |

**若改前就存在类型错误**：记录数量，并确认它们不掩盖新错误（或先修掉）。
**若不存在类型门禁**：先建一个再开始改。没有类型门禁的大范围重构等于盲改。

## 4. 数据资产

| 资产 | 路径 | 大小 | 形态（`file` 实测） | 备份位置 |
|---|---|---|---|---|
| {name} | {path} | {size} | {SQLite 3.x / LFS 指针 / ...} | {仓库外路径} |

- 备份完整性校验：`{命令}` → `{结果}`
- 恢复演练：{已实测恢复到 {临时路径}，结果 ok / 未做（说明原因）}
- **破坏性路径排查**：{发现的 `DROP TABLE` / `rmtree` / 无 WHERE 的 DELETE 列表}
- **测试是否污染真实数据**：{跑测试前后校验和对比结果}

## 5. 代码规模与结构（用于排期依据）

| 指标 | 值 | 统计命令 |
|---|---|---|
| 总行数 | {N} | `{命令}` |
| 文件数 | {N} | `{命令}` |
| 最大文件 | {name} {N} 行 | `{命令}` |
| 测试数 | {N} | — |
| 单文件最大测试 | {name} {N} 行 | `{命令}` |

> 这些数字是**门禁 07（工作量单位）** 的依据。不要凭感觉给估计。

## 6. 既有守卫（改之前有什么护栏）

| 守卫 | 位置 | 能失败吗（注入违规实测） |
|---|---|---|
| {name} | {path} | {是 / 否 —— 否的话它其实是假守卫} |

## 7. 结论：可以开始改了吗

- [ ] 回退命令实测过
- [ ] 测试基线是数字，不是"应该能过"
- [ ] 类型门禁存在且退出码 0
- [ ] 数据已备份到仓库外，且实测过可恢复
- [ ] 已知红灯已记录
- [ ] 至少有一条能失败的守卫

**任一未勾选 → 不许开始改造。** 先把这一项补上。
```

---

## 使用说明

**这份报告的价值不在"给人看"，而在于它让"改动有没有改变行为"变成一个可判断的问题。**

没有基线时，判断"有没有变坏"只能靠感觉。有了数字基线，就是 `139 → 188`，
**任何偏差都必须解释**。这也是为什么基线必须**先于**改动建立。
