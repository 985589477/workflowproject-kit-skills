# 门禁 01：基线固化

**触发**：任何改造、重构、迁移、换库、动 schema、动数据**之前**。包括"只是顺手清理一下"。

**为什么**：这是整套治理里**唯一让大范围改动可以安全推进**的东西。
在 StockTools 重构里，正是这一步（而不是任何文档）抓到了 **3 次真实误删**：

1. 类型门禁抓到跨度算法吞掉了相邻函数（`async function` 没被当边界）——
   在旧配置下会静默发布成**空白面板**，不报错、不进测试。
2. 静态扫描把 `.hot` 判成死 CSS，但它是**后端数据给出的类名**（运行时拼接），删了丢样式。
3. 空 `finally` 块不能整块删——`} finally {` 那一行**同时是 catch 的闭合括号**。

三次都是**可运行的检查**拦下的，没有一次是靠"看文档"或"仔细一点"。

---

## 必须产出（写进项目 `AGENTS.md`，不是写在这里）

```markdown
## 基线（{日期}）
- 回退命令：{实测过的一条命令，例如 git checkout <base> / 恢复备份路径}
- 测试基线：{N} passed（命令：{...}）
- 类型/lint 门禁：{有 / 无}（命令：{...}；退出码 0）
- 数据备份：{路径}（大小 {..}；完整性校验 {命令与结果}）
- 已知红灯（改前就存在的失败）：{列表 / 无}
```

## 检查方式

1. **回退命令必须实测一次**，不是从文档抄的。跑一次确认能回到基线，再开始改。
2. **测试基线必须是数字**。"大概都能过"不是基线。改完后对比数字：
   **数字变了就是行为变了**，必须解释。
3. **类型/lint 门禁若不存在，先建一个再改。** 没有类型门禁的重构等于盲改。
   注意有些构建命令**不做类型检查**（如 `vite build` 默认只转译），要单独跑 `tsc --noEmit`。
4. **数据资产先备份**（见门禁 08）。

## 反例（我实测踩到的）

| 反例 | 后果 |
|---|---|
| 仓库里有 .NET/Python 的 `PYTHONPATH` 依赖，靠"我记得设过" | 换会话就失败。基线里的命令必须是**实测可复制粘贴**的 |
| 只跑测试不建类型门禁 | 手写类型桩把 86 个真实类型错误全部掩盖；改完才发现面板是空的 |
| 基线只记"139 passed"，不记**命令** | 下一个人用错解释器跑出 0 passed，以为环境坏了 |
| 备份到仓库内（如 `./backup/`） | 一次 `git clean` 就没了。备份必须在**仓库外** |

## 与其他门禁的关系

- 产出依赖 **06 环境能力探测**（验证命令要实测可跑）。
- 数据类项目必须同时过 **08 数据资产保护**。
- 基线本身应该成为 **02 可运行守卫** 的第 0 号守卫（基线回归测试）。
