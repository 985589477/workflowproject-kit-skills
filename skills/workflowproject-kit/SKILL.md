# WorkflowProject 统一开发治理能力

## 0. 三条铁律（只读这三条；其余按需查）

1. **注入优于检索。** 规则只有写进**项目 `AGENTS.md`** 才会每轮生效（模板：`templates/project-agents.md`）。
   只写在对话里的规则下一轮就丢。
2. **门禁要能执行。** 每个门禁的产出必须是**可运行或可 diff 的东西**，不是一份清单。
   用 `scripts/check_gates.py` 校验。
3. **改造前先固化基线。** 没有可回退基线和可运行守卫，不许开始改造（门禁 01）。

> 本包刻意不设"必读链条"。**只读当前门禁指向的那一个文件。**
> 具体角色工作流直接加载对应能力包（`project-governance-kit` / `team-orchestration-kit` /
> `product-manager-kit` / `ui-designer-kit` / `developer-kit` / `tester-kit`），
> 不要按目录顺序通读。

## 1. 开跑门禁（先于一切；未输出不得动代码）

本包被加载后，无论任务看起来多简单，先输出下面这段，并**同时写进项目 `AGENTS.md`**
（只出现在对话里 = 下一轮丢失 = 违规）：

```text
项目归属：新项目 / 已有项目（{路径}）
模块归属：{扩展模块 / 新模块 / 待确认}
设计规范状态：已有 / 需建立最小规范 / 不适用
目标端与适配范围：{网页 / 移动端 / 桌面端 / 多端；横屏 / 分屏 / 折叠}
项目记忆：{已读文件 / 未找到}
执行模式：单 Agent + Skill / 父 Agent + 子 Agent
当前阶段：{阶段}
尺度：{行数} × {可写文件数} → 角色数 {n}
人工判断检查点：{必须用户亲自看的点，按先后顺序}
```

硬性规则：

- 设计规范状态只能是上面三种之一且必须被用户看见；猜一个或空着都算违规。
- 「需建立最小规范」时先确认范围，确认前不进实现。
- 涉及页面/组件/界面的任务不得写「不适用」。
- **用户换需求、换模块或换技术方案时，重新输出这段并重新落盘**，不得沿用上一轮结论。
- 这段必须落进项目 `AGENTS.md`，不能只在对话里。

## 2. 尺度选择（先判断，再决定用几个角色）

| 尺度 | 角色数 | 建子 Agent？ |
|---|---|---|
| ≤2k 行 / 单文件脚本 | 1 | 否，直接用本 Skill |
| 2k–20k 行 / 单人项目 | 1–2 | 仅在需要独立视角时建 1 个 |
| \>20k 行 / 跨模块改造 | 3–5 | 是（真实子 Agent，各自可写边界互不重叠） |

判据是**行数 × 可写文件数**，不是"任务听起来复杂"。小项目建 4 个角色 = 纯浪费。
运行环境没有真实子 Agent 工具时，必须说明并按上表降级，**不得伪装成子 Agent 协作**。

## 3. 门禁表（8 条；只点开当前需要的那一行）

| # | 触发条件 | 必须产出 | 检查方式 | 细节 |
|---|---|---|---|---|
| **01** | 任何改造/重构/迁移/换库**之前** | 基线报告：数据备份路径、测试基线数、类型或 lint 门禁状态、回退命令 | `check_gates.py` 校验基线段；回退命令实测一次 | [gates/01](gates/01-baseline-freeze.md) |
| **02** | 定下治理规则、架构约束、接口契约时 | **可运行守卫**（守卫测试 / 契约快照 / golden 文件），不是清单 | 注入一个故意违规，确认它变红 | [gates/02](gates/02-runnable-guards.md) |
| **03** | 读到项目文档（架构/规范/README）并准备依据它行动时 | 文档与代码的一致性结论；不一致处登记并修正文档 | 每条被引用的文档断言都要有代码证据 | [gates/03](gates/03-code-over-docs.md) |
| **04** | 规划阶段（列任务时） | 「必须用户亲自看」的检查点清单，且**排在前面** | 计划里能否找到该段 | [gates/04](gates/04-human-judgment-checkpoints.md) |
| **05** | 创建子 Agent 或接收其报告时 | 简报（目标/边界/验收/返回格式）+ 父 Agent 的复核记录 | 报告里有复核了哪几条的说明 | [gates/05](gates/05-subagent-contract.md) |
| **06** | 首次要在这个环境跑任何命令时 | 实测可跑的验证命令清单，写进项目 `AGENTS.md` | 逐条真跑一次，记录真实退出码 | [gates/06](gates/06-environment-probe.md) |
| **07** | 给工作量估计时 | 用**会话数**，并单列「必须等人的检查点数」 | 不得只给日历天数 | [gates/07](gates/07-effort-unit.md) |
| **08** | 仓库含数据库/二进制/大资产，且要改其结构时 | 备份路径 + 只做加法迁移的说明 | 备份可恢复性实测 | [gates/08](gates/08-data-asset-protection.md) |

**门禁的产出必须落盘**（项目 `AGENTS.md` 或 `docs/`），否则不算通过。
**没有被触发过的门禁就是死规则**——定期用 `check_gates.py --audit` 找出它，然后删掉或改触发条件。

## 4. 生命周期（原 11 条压缩）

```text
任务类型识别 → 技术方案问询 → 功能/组件问询 → 项目治理检查 → 架构与模块检查
→ 设计规范检查 → 整体规划 → 任务列表 → 逐条实现 → 逐条验证 → 文档与记忆同步
```

**分流**：简单单角色任务直接用本 Skill；组合任务才建真实子 Agent。
**缺输入时先问**，不要直接大范围改代码。

---

## 5. 保留的硬性规则

- **区分事实 / 推断 / 待确认**。结论必须能指到 `文件:行`；推断要标注是推断。
- **最小必要改动**：能删就不加，能复用就不新建。治理检查不通过时，先补治理再写功能。
- **输出位置**：产物写进项目已有的文档目录（如 `docs/`），不要新造目录。
- **一条一提交**：每个步骤结束时测试绿 + 类型检查 0 错误；红了就回退这一步，不要叠加。
- **同步文档**：代码/架构/模块/规范/任务状态变化后同步文档；**不一致时以代码为准**（门禁 03）。
- **收尾交接**：交接文档必须写清「现在能不能跑、怎么跑、下一步从哪开始、已知地雷」。

## 6. 收尾门禁（任务结束前）

1. 项目 `AGENTS.md` 的活状态段是否已更新（基线、验证命令、已解决/未解决清单）？
2. `check_gates.py` 是否通过？
3. 是否有未登记的"有意保留的捷径"？用 `ponytail:` 注释或台账登记，不要让它烂成"以后再说就是永远不做"。
