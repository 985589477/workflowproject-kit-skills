# 设计令牌标准

## 目的

规定 UI 设计如何输出可复用、可跨平台转换的设计令牌，避免把设计规范直接绑定到 CSS 或某一个 UI 框架。

## 三层输出模型

```text
设计意图与规则
-> 平台中立设计令牌
-> 目标平台适配文件
```

### 设计意图与规则

说明品牌方向、视觉层级、交互原则、布局规则、适配策略和组件行为。

### 平台中立设计令牌

作为设计系统的统一来源，至少覆盖：

- 原始色彩、字体、间距、圆角、阴影和动效值。
- 语义色彩、文字、边框、状态和层级。
- 字体族、字号、字重、行高和字间距。
- 间距、尺寸、容器、断点和密度。
- 组件级令牌，例如按钮、输入框、日历和导航。

推荐文件：

```text
design-tokens.json
```

### 目标平台适配文件

根据已确认的平台和框架，将中立令牌映射为平台实现：

| 平台 | 可能的实现文件 |
| --- | --- |
| Web | CSS Variables、主题配置、TypeScript Token |
| React Native | TypeScript Theme |
| iOS / SwiftUI | Swift Token、Color Set、Theme |
| Android / Compose | Kotlin Theme |
| Flutter | Dart Theme |
| 小程序 | WXSS、JSON 配置 |

## 核心规则

1. 未确认目标平台时，不默认输出 CSS。
2. 多平台项目只维护一套中立令牌，不手工维护多套互相独立的颜色和字号。
3. 组件优先使用语义令牌，不在组件中直接散落原始颜色值。
4. 原始令牌描述“是什么值”，语义令牌描述“用于什么场景”。
5. 设计令牌不能替代平台适配规则，字体渲染、单位、触控尺寸和系统安全区需要单独说明。
6. 令牌新增、修改和废弃需要说明影响范围以及是否兼容已有组件。

## 进入开发前必须确认

- 目标平台和 UI 框架。
- 样式、主题或设计令牌接入方式。
- 是否需要多平台共用令牌。
- 是否需要深色模式、高对比度或系统字体适配。
- 中立令牌文件和平台适配文件的维护位置。
- 哪些令牌允许开发调整，哪些属于设计不可变更边界。
