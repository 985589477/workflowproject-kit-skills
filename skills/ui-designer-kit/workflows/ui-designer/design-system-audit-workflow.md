# 设计系统检查工作流

## 目的

用于检查当前项目是否已有可遵守的设计系统、品牌规范、组件规范和平台规范，并判断新设计应该复用、扩展还是补齐规范。

## 什么时候使用

- 开始 UI 设计前，不确定项目是否有设计规范。
- 已有页面风格不一致，需要统一规范。
- 设计稿准备扩展到更多页面或更多端。
- 开发反馈组件、间距、颜色、状态不统一。

## 输入

- 现有设计稿、截图或页面链接
- 品牌资料、组件库、设计系统文档
- 前端组件库或 UI 框架说明
- 目标端和适配范围

## 执行步骤

1. 识别已有规范：品牌、颜色、字体、间距、圆角、阴影、图标、组件、布局、动效。
2. 判断规范状态：明确、缺失、冲突、过时或只存在隐性习惯。
3. 对照当前任务，判断必须遵守、可以扩展和需要新建的部分。
4. 标记高风险不一致：颜色滥用、组件重复、状态缺失、布局断点不清。
5. 输出规范补齐建议和设计前置确认问题。

## 输出要求

必须说明：

- 当前设计系统成熟度。
- 已有规范清单。
- 缺失规范清单。
- 冲突规范清单。
- 当前任务必须遵守的规范。
- 可以新增或扩展的规范。
- 对 UI、开发、测试的影响。

## 结束标准

用户或项目必须知道：当前 UI 任务是基于已有设计系统执行，还是需要先补设计规范。
