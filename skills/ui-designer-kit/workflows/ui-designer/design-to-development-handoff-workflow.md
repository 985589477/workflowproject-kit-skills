# 设计到开发实现约束工作流

## 目的

用于把 UI 设计方案转换成开发可实现、可估算、可验收的实现约束，减少设计交接后反复沟通。

## 什么时候使用

- UI 方案准备进入开发。
- 设计里存在响应式、多端、复杂组件、动效或特殊设备适配。
- 开发需要知道布局规则、组件边界、数据字段和状态处理。
- 设计交接文档缺少可实现细节。

## 输入

- UI brief、页面结构、组件说明、设计稿或截图
- 平台中立设计令牌和平台适配说明
- 响应式与多端适配方案
- 组件库规划
- 前端技术栈或 UI 框架

## 执行步骤

1. 梳理页面结构、布局容器和断点规则。
2. 确认令牌源文件、平台映射和实现文件位置。
3. 梳理组件清单、组件来源、组件状态和组件数据字段。
4. 明确交互反馈、加载、空态、错误、权限、极端数据。
5. 明确多端适配、特殊设备、安全区域和可访问性要求。
6. 输出开发实现注意事项、不可自行发挥项和可协商项。
7. 输出验收关注点，方便产品、设计、开发、测试对齐。

## 输出要求

必须说明：

- 页面结构实现规则。
- 设计令牌源文件和平台适配规则。
- 组件实现规则。
- 状态实现规则。
- 响应式和特殊设备实现规则。
- 数据和权限依赖。
- 动效与反馈约束。
- 开发可调整范围。
- 设计不可变更边界。
- 验收清单。

## 主动询问规则

如果技术栈、目标端、组件库、开发约束不清楚，先询问或标记为待开发确认。
