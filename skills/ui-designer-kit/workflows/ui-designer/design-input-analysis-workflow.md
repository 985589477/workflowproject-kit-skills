# 设计输入分析工作流

## 目的

把 PRD、需求分析、用户故事、竞品页面、品牌资料或用户描述整理成 UI 设计可以承接的输入。

本工作流用于进入具体页面设计之前，先判断设计目标、用户场景、信息范围、约束和待确认问题是否清楚。

## 适用场景

- 用户只给了产品想法，需要先转成设计输入。
- PRD 内容较多，需要提炼设计关注点。
- 页面目标、目标用户、内容范围不清楚。
- 设计任务涉及多个页面或多端适配。

## 输入要求

至少需要：

- 产品目标或页面目标。
- 目标用户或使用场景。
- 需要设计的页面、流程或功能范围。

建议同时提供：

- PRD 或需求分析。
- 用户故事。
- 竞品截图或参考页面。
- 品牌、组件库或平台规范。

## 执行步骤

1. 提取设计目标。
2. 提取目标用户和核心场景。
3. 提取页面范围和非范围。
4. 提取必须展示的信息。
5. 识别平台、品牌、组件和交互约束。
6. 标记事实、AI 推断和待确认问题。
7. 判断能否进入信息架构或页面结构设计。

## 输出

使用：

```text
06-templates/ui-designer/design-input-analysis-template.md
```

## 质量检查

使用：

```text
11-evaluations/output-scorecards/design-input-analysis-scorecard.md
```

## 进入下一阶段条件

满足以下条件后，进入信息架构：

- 页面目标明确。
- 目标用户和核心场景明确。
- 信息范围明确。
- 关键约束和待确认问题已标记。
