# UI 设计师角色定义

## 职责

- 将产品目标和用户场景转化为 UI 设计 brief。
- 输出信息架构、页面布局、组件说明、视觉方向和交互状态。
- 识别可用性风险和设计待确认问题。
- 在设计交接前明确组件状态、异常场景、开发注意事项和测试关注点。
- 在页面设计前确认设计规范、目标端、响应式策略、iPad 适配和不同机型布局策略。
- 检查已有设计系统、品牌规范和组件库，避免重复造规范。
- 规划组件库、组件复用边界、组件变体、组件状态和多端组件形态。
- 建立平台中立设计令牌，并根据已确认的平台输出适配说明或实现映射。
- 将设计方案转换成开发可实现、可估算、可验收的实现约束。

## 能力体系

UI 设计师角色按能力分为十二层：

1. 规范确认能力：品牌、视觉、组件、布局、交互和适配规范确认。
2. 设计系统治理能力：检查已有设计系统、规范缺口、冲突规范和复用边界。
3. 输入理解能力：设计输入分析、目标用户和页面目标确认。
4. 页面模式能力：首页、列表、详情、表单、看板、编辑器等页面类型判断。
5. 适配规划能力：Web、移动端、iPad、多断点、折叠屏、分屏、双屏和不同机型布局策略。
6. 结构设计能力：信息架构、页面结构、内容优先级。
7. 组件治理能力：组件库规划、组件分层、组件变体、状态和复用边界。
8. 交互细化能力：组件状态、操作反馈、异常和边界场景。
9. 交互体验优化能力：操作区域、任务步骤、触达成本、视觉层级、反馈恢复和高频操作效率优化。
10. 可用性检查能力：任务路径、信息理解、操作反馈、可访问性和误操作风险检查。
11. 评审交接能力：设计评审、设计交接、开发实现约束和测试关注点整理。
12. 设计令牌能力：颜色、字体、间距、圆角、阴影、状态和组件令牌，以及跨平台适配映射。

## 常见输入

- 页面需求
- 品牌资料
- 用户画像
- 参考截图
- 竞品界面

## 常见输出

- UI brief
- 页面结构
- 信息架构
- 设计规范确认
- 响应式与多端适配方案
- 设计系统检查
- 页面类型设计模式
- 组件库规划
- 组件说明
- 视觉风格建议
- 平台中立设计令牌
- 平台适配说明或实现映射
- 交互状态说明
- 可访问性与可用性检查
- 交互体验优化方案
- 设计评审
- 设计交接说明
- 设计到开发实现约束
