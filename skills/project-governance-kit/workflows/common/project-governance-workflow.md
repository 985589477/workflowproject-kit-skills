# 项目治理与开发前置工作流

## 目的

本工作流是 WorkflowProject 面向真实代码项目的通用主流程。

它不负责替代产品、UI、开发或测试角色，也不替用户静默决定技术方案。它负责检查项目是否具备可控开发的基础：技术基线、架构、模块、设计规范、任务列表、模块文档和验证规则。

## 什么时候使用

- 新项目准备开始长期开发。
- 用户准备让 AI 接手已有项目。
- 项目缺少架构、模块或设计文档。
- 用户提出新需求，但不确定应该先补什么。
- AI 需要在真实项目中持续修改代码。
- 项目出现文档、代码和任务状态不一致。

## 核心路由

```text
用户提出任务
-> 读取项目规则入口
-> 检查治理材料
-> 判断项目复杂度和风险
-> 输出缺口与待确认问题
-> 补齐或确认项目事实
-> 形成整体功能规划
-> 生成任务列表
-> 按任务逐条实现和验证
-> 同步模块文档与项目记忆
-> 评审并判断下一步
```

## 第一步：读取项目入口

优先查找：

```text
AGENTS.md
AI-WORKFLOW-RULES.md
.cursor/rules/
README.md
docs/
package.json、pyproject.toml、Cargo.toml、go.mod 等技术栈入口
```

记录已经读取的文件，不要声称读取不存在的规则。

## 第二步：检查治理材料

检查项目是否已有：

```text
项目说明
架构概览
模块地图
模块边界文档
设计系统或设计规范
组件和适配规则
开发规范
测试规范
任务列表
模块文档
项目记忆摘要
```

同时检查技术基线：

```text
目标平台
主要语言
框架及版本
运行时和包管理器
构建、启动和部署方式
测试工具和测试命令
浏览器、设备或系统支持范围
```

对每项标记：

```text
完整 / 部分存在 / 缺失 / 与代码不一致 / 待用户确认
```

## 第三步：判断复杂度

| 类型 | 处理方式 |
| --- | --- |
| 轻量任务 | 读取相关入口，输出轻量计划，直接完成小范围修改并验证 |
| 普通功能 | 补充影响分析、模块规划、任务列表和验证计划 |
| 多模块功能 | 补充架构、模块边界、契约、任务列表和交接说明 |
| 高风险功能 | 增加安全、权限、数据迁移、发布和回滚检查，并等待关键确认 |

## 第四步：交互式补齐

如果缺少关键材料，先输出：

```text
当前缺少：{文档或信息}
影响：{不补齐可能导致什么问题}
可以从项目事实推断：{内容}
需要用户确认：{问题}
建议补齐方式：{最小方案 / 完整方案}
```

以下内容不能静默猜测：

- 核心模块职责。
- 数据和接口归属。
- 权限和安全边界。
- 设计方向和品牌规范。
- 设备适配范围。
- 新项目使用的语言、框架、运行时和测试方案。
- 新模块是否沿用现有技术栈，或是否允许引入独立技术栈。
- 破坏性改动和发布策略。

### 技术方案问询

如果是新项目，先询问：

```text
1. 目标平台是什么？
2. 主要使用什么语言？
3. 是否指定框架及版本？
4. 运行、构建和部署环境是什么？
5. 测试希望使用什么工具或方式？
```

如果是已有项目的新模块，先报告当前项目识别到的技术栈，再询问：

```text
当前项目技术栈为：{语言 / 框架 / 运行时 / 构建方式}。
新模块是否沿用这套技术栈？是否允许引入新的语言、框架或独立运行时？
```

在用户确认前，不创建依赖该选择的工程文件、模块骨架或代码。

## 第五步：形成整体规划

进入代码前，必须说明：

- 用户目标。
- 本次范围和明确不做的内容。
- 受影响的模块、文件、接口、数据和配置。
- 模块之间如何协作。
- 需要调用哪些专业角色或工作流。
- 如何验证。
- 哪些内容仍需用户确认。

## 第六步：生成任务列表

任务列表每条任务至少包含：

```text
编号、目标、影响范围、前置依赖、验收标准、验证方式、状态、阻塞原因
```

默认一次只执行一条任务。只有当前任务完成并验证后，才进入下一条。

## 第七步：同步文档

代码变更影响以下内容时必须检查是否同步：

```text
架构概览
模块地图
模块边界
设计规范
接口或状态契约
任务列表
测试记录
项目记忆摘要
```

不要求每次都修改所有文档，但必须说明检查结果和不修改的理由。

## 角色调用原则

默认由团队总调度判断是否需要角色能力。

角色能力只负责专业判断：

- 产品经理：需求和验收。
- UI 设计师：设计、组件和适配。
- 开发工程师：架构、模块和实现。
- 测试工程师：质量、回归和发布验收。

如果只是项目治理检查，不必强制调用所有角色。

## 结束标准

结束时必须报告：

- 已读取的项目规则和事实文档。
- 当前治理缺口。
- 已完成的任务和验证结果。
- 未完成任务和阻塞原因。
- 已同步和未同步的项目文档。
- 是否存在需要用户确认的问题。
- 下一步应该进入哪个阶段。
