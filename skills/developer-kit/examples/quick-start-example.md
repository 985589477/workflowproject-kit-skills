# 快速启动示例

## 示例任务

用户输入：

```text
请使用 developer-kit 协助我处理这个开发任务：
我有一个现有 React 项目，想新增一个导出报告功能。
```

## AI 应该先输出什么

```text
当前阶段：任务识别
任务判断：产品需求进入开发
调用能力包：developer-kit
使用工作流：workflows/developer/developer-kit-workflow.md
执行方式：先分析和规划，暂不直接改代码
风险等级：中
是否需要用户确认：需要在功能规划后确认是否进入实现
下一步：进入需求理解和项目理解
```

## AI 不应该怎么做

不要直接输出：

```text
我会新增 ExportButton.jsx，然后修改 App.jsx。
```

原因：

- 尚未理解项目结构。
- 尚未判断导出报告的数据来源。
- 尚未确认导出格式。
- 尚未判断影响模块和验证方式。

## 正确推进方式

### 第 1 步：需求理解

AI 应先确认：

```text
需求目标：新增导出报告功能。
待确认问题：
1. 导出格式是 PDF、Excel、CSV 还是图片？
2. 报告数据来自当前页面、接口还是本地状态？
3. 导出入口放在哪里？
4. 是否需要权限控制？
```

如果用户已经说明这些信息，可以继续。

### 第 2 步：项目理解

AI 应阅读项目结构，输出：

```text
当前阶段：项目理解
已识别模块：
- 页面模块
- 数据请求模块
- 组件模块
- 工具函数模块
可能影响：
- 报告展示页面
- 数据聚合逻辑
- 导出工具函数
- 测试用例
```

### 第 3 步：功能整体规划

AI 应在实现前输出：

```text
当前阶段：功能整体规划
本次包含：
- 新增导出入口。
- 新增导出工具函数。
- 接入当前报告数据。
- 增加最小验证。

本次不包含：
- 批量导出。
- 权限系统重构。
- 后端接口改造。

实现顺序：
1. 确认数据来源。
2. 新增导出工具函数。
3. 接入页面按钮。
4. 增加测试或手动验证。
5. 同步文档。

是否需要用户确认：需要。
```

### 第 3.2 步：项目规范检查

进入实现前，AI 应先检查项目规范：

```text
项目规范检查：
- 设计规范：{已找到 / 未找到 / 不涉及}
- 组件规范：{已找到 / 未找到 / 不涉及}
- 交互规范：{已找到 / 未找到 / 不涉及}
- 代码规范：{已找到 / 未找到}
- 测试规范：{已找到 / 未找到}
- AI 协作规则：{已找到 / 未找到}
- 本次将遵守：{具体文件或从现有代码归纳的临时约定}
- 需要确认：{缺失但影响实现的问题}
```

### 第 3.5 步：开发任务拆解

用户确认进入实现后，AI 应先拆成开发任务列表：

```text
| 序号 | 任务 | 目标 | 影响文件或模块 | 前置依赖 | 验收标准 | 验证方式 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 确认报告数据来源 | 找到导出需要的数据结构 | 报告页面、数据 hooks | 无 | 明确字段来源 | 阅读代码/类型检查 | 待执行 |
| 2 | 新增导出工具函数 | 生成可下载文件 | utils/export | 任务 1 | 能生成目标格式 | 单元测试/手动验证 | 待执行 |
| 3 | 接入页面入口 | 用户可点击导出 | 报告页面组件 | 任务 2 | 点击后触发导出 | 手动验证 | 待执行 |
```

执行时一次只做一条任务，并在进入下一条前记录验证结果。

### 第 4 步：用户确认后实现

用户确认后，AI 才进入：

```text
implementation-workflow.md
```

### 第 5 步：实现后收尾

实现后必须输出：

```text
当前阶段：测试验证 / 文档同步 / 代码评审
已修改文件：
- ...
验证结果：
- ...
未验证内容：
- ...
下一步：
- 是否需要发布检查。
- 是否需要复盘沉淀。
```

## 结束条件

这个任务不能只在“代码写完”时结束。

至少要说明：

- 实现是否完成。
- 验证是否完成。
- 文档是否需要同步。
- 是否还有待确认问题。
- 下一步是否进入发布或复盘。
