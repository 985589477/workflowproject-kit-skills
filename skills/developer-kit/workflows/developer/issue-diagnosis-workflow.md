# 问题定位工作流

## 目的

当用户反馈报错、异常、白屏、接口失败、性能变慢、测试失败或线上问题时，帮助 AI 先定位问题，再决定是否进入修复实现。

问题定位工作流不直接替代代码实现。它的核心价值是避免 AI 在原因不清时凭感觉改代码。

## 适用场景

适用于：

- 页面白屏、控制台报错、接口异常、测试失败。
- 用户说“这里坏了”“跑不起来”“性能很慢”。
- 问题可能涉及多个模块、配置、依赖或环境。
- 修复前需要复现、定位调用链、判断根因。

不适用于：

- 已经明确原因且低风险的小修复。
- 用户只要求代码评审。
- 用户只要求上线检查。

## 输入要求

至少提供以下一种：

- 问题现象。
- 报错信息。
- 复现步骤。
- 相关截图或日志。
- 受影响页面、接口、命令或测试。
- 最近改动范围。

如果缺少复现信息，应先询问用户或输出最小复现假设。

## 执行原则

### 1. 先复现，再修复

不能复现时，不要把猜测当结论。应说明当前只能做静态排查或假设分析。

### 2. 区分现象、证据和推断

输出必须区分：

```text
已确认现象
已找到证据
AI 推断
待确认问题
```

### 3. 先定位责任域

先判断问题更可能属于：

- 前端渲染。
- 组件状态。
- API 请求。
- 后端服务。
- 数据结构。
- 权限认证。
- 环境配置。
- 依赖版本。
- 构建或测试配置。

### 4. 修复前先判断风险

如果修复会影响核心流程、数据结构、权限、安全、生产配置或跨模块调用，必须进入风险评估。

## 执行步骤

### 第 1 步：整理问题输入

确认：

- 问题现象。
- 发生环境。
- 触发入口。
- 复现步骤。
- 报错日志。
- 最近相关改动。

产出：问题输入摘要。

### 第 2 步：判断是否可复现

输出：

| 项目 | 结论 |
| --- | --- |
| 是否可复现 | 是 / 否 / 未验证 |
| 复现方式 | 命令 / 页面路径 / 操作步骤 |
| 复现结果 | 现象、日志、失败位置 |

如果不能复现，说明缺少什么信息。

### 第 3 步：定位责任域

按证据判断问题属于哪里：

| 责任域 | 是否相关 | 证据 | 备注 |
| --- | --- | --- | --- |
| 前端页面 |  |  |  |
| 组件状态 |  |  |  |
| API 请求 |  |  |  |
| 后端服务 |  |  |  |
| 数据结构 |  |  |  |
| 权限认证 |  |  |  |
| 环境配置 |  |  |  |
| 依赖构建 |  |  |  |

### 第 4 步：追踪调用链

梳理：

- 用户入口。
- 页面或命令入口。
- 调用函数。
- 依赖模块。
- 数据来源。
- 异常抛出点。
- 输出或失败位置。

产出：问题调用链。

### 第 5 步：形成根因假设

每个假设必须包含：

```text
假设
支持证据
反证或不确定点
验证方式
修复方向
风险
```

### 第 6 步：给出修复策略

根据定位结果决定下一步：

| 情况 | 下一步 |
| --- | --- |
| 根因明确且低风险 | 进入 `implementation-workflow.md` |
| 根因明确但影响较大 | 进入 `change-risk-assessment-workflow.md` 和 `impact-analysis-workflow.md` |
| 涉及接口或数据契约 | 进入 `data-api-contract-workflow.md` |
| 涉及权限或安全 | 进入 `security-permission-workflow.md` |
| 根因不明确 | 补充复现、日志或继续只读排查 |

## 推荐输出结构

```md
# 问题定位报告

## 问题摘要

## 复现情况

## 已确认事实

## 责任域判断

## 调用链分析

## 根因假设

| 假设 | 证据 | 不确定点 | 验证方式 | 修复方向 | 风险 |
| --- | --- | --- | --- | --- | --- |

## 推荐修复策略

## 需要用户确认的问题

## 推荐下一步工作流
```

## 与其他 developer-kit 工作流的关系

| 关系 | 工作流 | 说明 |
| --- | --- | --- |
| 前置 | `project-understanding-workflow.md` | 不理解项目时先理解项目。 |
| 当前 | `issue-diagnosis-workflow.md` | 定位问题和根因。 |
| 后续 | `implementation-workflow.md` | 根因明确后修复。 |
| 后续 | `data-api-contract-workflow.md` | 涉及接口、状态或数据契约时使用。 |
| 后续 | `security-permission-workflow.md` | 涉及权限、安全或敏感数据时使用。 |

## 快速启动话术

```text
请使用问题定位工作流分析下面的问题。

问题现象：
报错信息：
复现步骤：
相关文件或模块：

请先不要修复，先输出复现情况、责任域判断、调用链、根因假设、修复策略和下一步工作流。
```

## 质量要求

- 必须区分事实、证据、推断和待确认问题。
- 必须说明是否已经复现。
- 必须说明责任域判断。
- 必须输出根因假设和验证方式。
- 不能在根因不清时直接大范围修改代码。
