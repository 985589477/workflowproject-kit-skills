# 环境与配置治理工作流

## 目的

在项目长期维护中，帮助 AI 管理环境变量、启动配置、构建配置、部署配置和不同环境之间的差异。

本工作流重点解决：

1. 项目需要哪些环境变量和配置。
2. 哪些配置不能提交到仓库。
3. 本地、测试、预发、生产环境有哪些差异。
4. 配置变更会影响哪些启动、构建、测试和部署流程。
5. 配置问题如何验证和回滚。

一句话：

```text
环境与配置治理 = 让项目在不同环境里可启动、可构建、可部署、可追踪。
```

## 适用场景

适用于：

- 新增或修改环境变量。
- 修改启动命令、构建命令或部署配置。
- 接入外部服务、密钥、API 地址、存储、数据库或消息队列。
- 处理本地、测试、预发、生产环境差异。
- 排查因配置导致的启动、构建或部署问题。
- 需要补充 `.env.example`、配置说明或部署文档。

不适用于：

- 与环境无关的纯业务代码修改。
- 用户只要求一次性本地实验，且不进入项目主线。
- 已有配置规范足够清晰且本次没有配置变化。

## 输入要求

至少需要：

- 配置变更目标。
- 当前项目环境或配置文件线索。

建议同时提供：

- `.env.example`、配置说明、部署文档。
- `package.json`、`pyproject.toml`、`Dockerfile`、CI 配置等入口文件。
- 本地、测试、生产环境差异。
- 相关密钥或服务说明，但不要提供真实密钥。
- 配置变更风险评估。

## 执行原则

### 1. 敏感信息不得入库

不得将真实密钥、token、密码、证书、生产连接串写入仓库文档或示例文件。

示例文件只能写：

```text
PLACEHOLDER
your_api_key_here
example.com
```

### 2. 配置来源必须明确

每个配置项应说明：

```text
名称
用途
是否必填
默认值
来源
适用环境
缺失后果
```

### 3. 环境差异必须记录

本地、测试、预发、生产的差异不能只靠记忆，应明确记录。

### 4. 配置变更必须有验证

修改配置后应验证：

- 本地启动。
- 构建。
- 测试。
- 部署或部署前检查。
- 外部服务连接。

### 5. 高风险配置需要确认

涉及生产配置、数据库、权限、安全、支付、用户数据和部署流水线时，必须等待人工确认。

## 执行步骤

### 第 1 步：识别配置对象

判断本次涉及：

- 环境变量。
- 启动命令。
- 构建命令。
- 部署配置。
- CI/CD 配置。
- Docker 或容器配置。
- 第三方服务配置。
- 数据库或缓存配置。
- 权限或安全配置。

产出：配置对象清单。

### 第 2 步：梳理现有配置

读取并整理：

```text
.env.example
README
AGENTS
docs/environment.md
package.json / pyproject.toml / Cargo.toml / go.mod
Dockerfile / docker-compose
CI 配置
部署说明
```

产出：现有配置摘要。

### 第 3 步：分析配置变更

说明：

- 新增什么配置。
- 修改什么配置。
- 移除什么配置。
- 哪些环境受影响。
- 缺失配置会发生什么。
- 错误配置会发生什么。

产出：配置变更分析。

### 第 4 步：识别风险

重点检查：

- 是否涉及真实密钥。
- 是否影响生产。
- 是否影响登录、权限、支付、数据。
- 是否影响构建或部署。
- 是否存在环境差异未记录。
- 是否缺少示例或默认值。
- 是否缺少回滚方案。

产出：配置风险清单。

### 第 5 步：制定治理方案

根据情况输出：

- `.env.example` 更新建议。
- 配置说明文档。
- README 启动说明更新。
- AGENTS AI 协作规则更新。
- CI/CD 或部署文档更新。
- 验证命令。
- 回滚方式。

产出：治理方案。

### 第 6 步：输出环境与配置治理报告

报告必须包含：

```text
配置对象
现有配置摘要
配置变更分析
环境差异
风险清单
治理方案
验证要求
回滚要求
文档同步建议
```

## 快速启动话术

```text
请参考 04-workflows/developer/environment-config-governance-workflow.md，
帮我评估这个环境/配置变更。

配置变更：
【粘贴说明】

请输出配置对象、现有配置摘要、配置项清单、环境差异、风险清单、治理方案、验证要求、回滚要求和文档同步建议。
```

## 质量要求

- 不得写入真实密钥或敏感信息。
- 必须说明配置项用途、必填性、适用环境和缺失后果。
- 必须记录环境差异。
- 生产、权限、安全、支付、数据相关配置必须高风险处理。
- 必须说明验证和回滚要求。
