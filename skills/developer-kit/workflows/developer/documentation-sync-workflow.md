# 文档同步工作流

## 目的

在代码实现和验证完成后，帮助 AI 判断哪些项目文档需要同步更新，并以最小必要范围更新文档。

本工作流重点解决：

1. 代码变化后哪些文档会失真。
2. README、AGENTS、docs、API、架构和模块文档是否需要同步。
3. 如何避免为了“看起来完整”而乱改文档。
4. 如何记录未同步文档的原因和风险。
5. 如何让后续 AI 能通过文档理解最新项目状态。

一句话：

```text
文档同步 = 让项目说明跟上真实代码，而不是变成旧地图。
```

## 适用场景

适用于：

- 代码实现已经完成。
- 测试与验收已经完成或已有验证结果。
- 本次变更影响启动方式、配置、接口、模块边界、架构、使用方式或开发规范。
- 用户希望后续 AI 能读取最新项目文档。
- 需要输出变更说明或维护记录。

不适用于：

- 只读分析。
- 没有代码、配置、接口、架构或使用方式变化。
- 用户明确要求暂不更新文档。

## 输入要求

至少需要：

- 实现交付说明或修改文件清单。
- 测试与验收结果。

建议同时提供：

- 影响范围分析报告。
- 变更风险评估报告。
- 当前 README、AGENTS、docs 目录。
- API 或模块文档路径。
- 用户指定不希望改动的文档。

## 执行原则

### 1. 事实变化才同步

只有当代码、配置、接口、流程、命令、架构或模块边界发生事实变化时，才更新相关文档。

### 2. 最小必要更新

只更新与本次变更相关的文档，不借机重写整份文档。

### 3. 文档服务后续协作

同步后的文档应该帮助未来的用户和 AI 快速理解：

```text
项目怎么运行
模块怎么分工
接口怎么使用
变更带来什么影响
如何验证
有哪些风险
```

### 4. 不确定内容要标注

无法确认的内容不要写成事实，应标注为待确认。

### 5. 用户已有文档风格优先

遵循项目已有文档结构、语气、命名和格式。

## 文档类型

| 文档 | 何时需要同步 |
| --- | --- |
| `README.md` | 启动方式、使用方式、项目能力、安装步骤变化。 |
| `AGENTS.md` | AI 协作规则、测试命令、危险操作规则、交付要求变化。 |
| `.cursor/rules/` | Cursor 协作规则或项目约束变化。 |
| `docs/development-standard.md` | 开发规范、目录规则、测试规则变化。 |
| `docs/architecture/` | 模块边界、架构、调用链、数据流变化。 |
| API 文档 | 接口、参数、返回、错误码变化。 |
| 配置文档 | 环境变量、部署配置、依赖配置变化。 |
| 变更说明 | 用户需要了解本次变更内容和验证结果。 |

## 执行步骤

### 第 1 步：读取变更事实

确认：

- 修改了哪些文件。
- 变更了哪些行为。
- 验证了什么。
- 哪些内容未验证。
- 是否有剩余风险。

产出：变更事实摘要。

### 第 2 步：判断文档影响

逐类判断是否需要同步：

```text
README
AGENTS
Cursor rules
开发规范
架构文档
模块文档
API 文档
配置文档
测试文档
变更说明
```

产出：文档影响清单。

### 第 3 步：选择同步策略

按影响选择策略：

| 策略 | 适用情况 |
| --- | --- |
| 不同步 | 文档事实未变化。 |
| 小范围补充 | 命令、路径、说明、示例有小变化。 |
| 局部改写 | 某一章节已经与代码不一致。 |
| 新增文档 | 现有文档没有承载位置。 |
| 待确认 | 内容无法确认或涉及产品/架构决策。 |

产出：同步策略。

### 第 4 步：执行文档更新

更新时遵守：

- 保持原有结构和风格。
- 不改无关章节。
- 不把推断写成事实。
- 不删除仍有效的历史说明。
- 对未验证内容明确标注。

产出：文档变更。

### 第 5 步：检查文档一致性

检查：

- 路径是否正确。
- 命令是否和项目文件一致。
- 模块名称是否一致。
- API 参数是否一致。
- 验证结果是否如实记录。
- 是否存在旧说法和新说法冲突。

产出：文档一致性检查结果。

### 第 6 步：输出文档同步报告

报告必须包含：

```text
变更事实
文档影响判断
已更新文档
未更新文档及原因
待确认内容
一致性检查
后续建议
```

## 推荐输出结构

```md
# 文档同步报告

## 变更事实

## 文档影响判断

| 文档 | 是否需要同步 | 原因 | 动作 |
| --- | --- | --- | --- |

## 已更新文档

| 文档 | 更新内容 |
| --- | --- |

## 未更新文档

| 文档 | 原因 | 风险 |
| --- | --- | --- |

## 待确认内容

## 一致性检查

## 后续建议
```

## 快速启动话术

```text
请参考 04-workflows/developer/documentation-sync-workflow.md，
基于本次代码变更和验证结果，判断哪些文档需要同步。

请只做必要文档更新，不要重写无关内容。

完成后输出文档同步报告，说明已更新文档、未更新文档、待确认内容和一致性检查结果。
```

## 质量要求

- 必须基于真实变更事实判断文档影响。
- 不得把推断写成事实。
- 不得大范围重写无关文档。
- 必须说明未更新文档的原因。
- 必须检查文档中的路径、命令、模块名和验证结果一致性。
