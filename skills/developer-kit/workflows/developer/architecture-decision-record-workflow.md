# 架构决策记录工作流

## 目的

当项目出现关键技术或架构选择时，帮助 AI 记录决策背景、备选方案、取舍原因、影响范围和后续复盘点。

本工作流重点解决：

1. 为什么选择这个架构方案。
2. 当时有哪些备选方案。
3. 放弃其他方案的原因是什么。
4. 这个决策会影响哪些模块、数据、接口、部署或维护成本。
5. 后续如果要推翻或调整决策，应看哪些条件。

一句话：

```text
架构决策记录 = 给未来的自己和 AI 留下“为什么这样设计”的证据。
```

## 适用场景

适用于：

- 选择技术栈、框架、库或关键依赖。
- 调整项目目录结构或模块边界。
- 设计跨模块协作方式。
- 决定数据模型、状态管理、缓存、权限、部署或集成方式。
- 选择临时方案、折中方案或迁移路径。
- 评审中发现需要记录的架构取舍。

不适用于：

- 普通文案、样式、小 bug 修复。
- 没有长期影响的一次性实现细节。
- 已经有清晰既定规范且没有产生新决策的变更。

## 输入要求

至少需要：

- 决策主题。
- 决策背景。
- 当前推荐方案。

建议同时提供：

- 需求到架构影响分析报告。
- 模块边界分析报告。
- 变更风险评估报告。
- 代码评审报告。
- 备选方案。
- 项目约束，例如时间、团队、技术栈、性能、安全、成本。

## 执行原则

### 1. 只记录真正的决策

ADR 不记录所有开发细节，只记录会影响未来维护、扩展、协作或风险的决策。

### 2. 记录取舍，不只记录结论

必须说明为什么选当前方案，以及为什么没有选择其他方案。

### 3. 区分事实、假设和待验证

不能把尚未验证的判断写成确定事实。

### 4. 决策应可追溯

应包含状态、日期、背景、方案、影响、风险和复盘条件。

### 5. ADR 不替代实现

ADR 记录决策，不直接写代码。实现仍应进入 `implementation-workflow.md`。

## ADR 状态

| 状态 | 含义 |
| --- | --- |
| 提议中 | 决策尚未确认，需要讨论。 |
| 已接受 | 当前项目采用该决策。 |
| 已废弃 | 该决策不再推荐，但历史仍保留。 |
| 已替代 | 该决策被新的 ADR 替代。 |
| 待复盘 | 决策生效后需要在特定条件下复查。 |

## 执行步骤

### 第 1 步：判断是否需要 ADR

检查本次事项是否影响：

- 技术栈。
- 架构结构。
- 模块边界。
- 数据模型。
- 状态管理。
- 接口协议。
- 权限和安全。
- 部署和运维。
- 长期维护成本。

产出：是否需要 ADR 的判断。

### 第 2 步：明确决策背景

说明：

```text
问题是什么
为什么现在需要决策
已有约束
不能接受的结果
相关上下文
```

产出：决策背景。

### 第 3 步：整理备选方案

至少记录：

- 当前推荐方案。
- 备选方案 A。
- 备选方案 B。
- 保持现状。

每个方案说明优点、缺点、成本和风险。

产出：备选方案对比。

### 第 4 步：形成决策

说明：

- 最终选择。
- 选择理由。
- 放弃其他方案的理由。
- 决策状态。
- 决策日期。

产出：决策结论。

### 第 5 步：分析影响和风险

分析该决策影响：

- 模块。
- 数据。
- API。
- 测试。
- 文档。
- 性能。
- 安全。
- 部署。
- 后续扩展。
- 技术债。

产出：影响与风险分析。

### 第 6 步：定义复盘条件

说明什么情况下需要重新看这个决策：

- 性能不达标。
- 复杂度超过预期。
- 业务规模变化。
- 团队能力变化。
- 依赖不可维护。
- 新方案成熟。
- 风险实际发生。

产出：复盘条件。

### 第 7 步：输出 ADR 文档

推荐放置位置：

```text
docs/decisions/
docs/architecture/decisions/
```

如果项目没有文档目录，可建议先创建 `docs/decisions/`。

```md

状态：提议中 / 已接受 / 已废弃 / 已替代 / 待复盘
日期：YYYY-MM-DD

## 背景

## 决策

## 备选方案

| 方案 | 优点 | 缺点 | 成本 | 风险 |
| --- | --- | --- | --- | --- |

## 选择理由

## 放弃方案的原因

## 影响范围

## 风险与代价

## 复盘条件

## 相关文档
```

## 质量要求

- 必须说明是否真的需要 ADR。
- 必须记录备选方案和放弃原因。
- 必须区分事实、假设和待验证内容。
- 必须说明影响范围和风险代价。
- 必须给出复盘条件。
- 不能把 ADR 写成普通开发日志。
