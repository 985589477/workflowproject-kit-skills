# 变更风险评估工作流

## 目的

在代码修改前，帮助 AI 判断本次变更的风险等级，并决定是否可以直接执行、是否需要先输出方案、是否必须等待人工确认。

本工作流重点解决：

1. 哪些变更可以直接做。
2. 哪些变更需要先做影响分析。
3. 哪些变更必须先给方案并等待确认。
4. 哪些操作属于危险变更，AI 不能擅自执行。
5. 本次变更需要哪些验证和回滚准备。

一句话：

```text
变更风险评估 = 给 AI 开发动作加一个执行权限闸门。
```

## 适用场景

适用于：

- 准备修改代码前。
- 需求涉及多个文件、模块或接口。
- 需求涉及数据、权限、登录、支付、配置、部署或迁移。
- 用户不确定这次变更风险大不大。
- AI 准备执行删除、重构、依赖升级、批量修改等操作。

不适用于：

- 用户只是询问概念。
- 只读分析，不涉及修改。
- 已经明确是低风险且用户要求快速处理的小改动。

低风险任务可以轻量评估，但仍要在交付说明中写清验证结果。

## 输入要求

至少需要：

- 变更目标或需求。
- 当前项目理解，或相关模块说明。

建议同时提供：

- 架构影响分析报告。
- 模块边界分析报告。
- 预计修改文件。
- 相关测试命令。
- 是否涉及生产环境、用户数据或外部服务。

## 风险等级

| 等级 | 判断标准 | AI 执行策略 |
| --- | --- | --- |
| 低风险 | 文案、样式、注释、单文件小 bug、无数据结构变化 | 可直接执行，完成后说明验证 |
| 中风险 | 单模块功能、局部状态、局部接口、少量文件变更 | 先说明方案和影响，再执行 |
| 高风险 | 跨模块、核心流程、权限、登录、支付、数据结构变化、复杂状态 | 先输出方案和风险，等待用户确认 |
| 危险变更 | 删除数据、数据迁移、批量重构、生产配置、破坏性命令、不可逆操作 | 必须人工确认，默认不执行 |

## 高风险信号

出现以下情况，应至少判为高风险：

- 修改登录、权限、支付、订单、账号、生产配置。
- 修改数据结构、持久化逻辑或迁移脚本。
- 影响多个核心模块。
- 可能破坏已有用户数据。
- 涉及安全、隐私、合规。
- 缺少测试但影响核心流程。
- 需要批量替换或大范围重构。

## 危险操作信号

出现以下情况，应判为危险变更：

- 删除数据库、文件、用户数据或生产资源。
- 执行不可逆迁移。
- 执行破坏性命令。
- 批量删除、移动或覆盖大量文件。
- 修改生产密钥、生产部署配置或线上资源。
- 绕过测试、权限或安全检查。

## 执行步骤

### 第 1 步：理解变更目标

明确：

```text
要改什么
为什么要改
影响谁
成功标准是什么
不做范围是什么
```

产出：变更目标摘要。

### 第 2 步：识别影响对象

判断是否影响：

- 页面或组件。
- 业务模块。
- API。
- 数据模型。
- 状态管理。
- 权限和登录。
- 配置和环境。
- 构建和部署。
- 测试。
- 文档。

产出：影响对象清单。

### 第 3 步：识别风险信号

检查：

- 是否跨模块。
- 是否改核心流程。
- 是否改数据结构。
- 是否涉及用户数据。
- 是否涉及权限、安全、支付。
- 是否缺少测试。
- 是否需要批量改动。
- 是否存在不可逆操作。

产出：风险信号清单。

### 第 4 步：判定风险等级

按低、中、高、危险四级判断，并说明原因。

产出：风险等级结论。

### 第 5 步：制定执行策略

根据风险等级输出策略：

| 等级 | 策略 |
| --- | --- |
| 低风险 | 可直接执行，完成后说明改动和验证。 |
| 中风险 | 先说明方案、影响文件和验证方式，再执行。 |
| 高风险 | 先输出方案、风险、回滚思路和确认问题，等待用户确认。 |
| 危险变更 | 默认不执行，只输出风险说明、替代方案和必须确认项。 |

产出：执行策略。

### 第 6 步：定义验证和回滚要求

说明：

- 需要跑哪些测试。
- 是否需要手动验收。
- 是否需要数据备份。
- 是否需要回滚方案。
- 是否需要文档同步。

产出：验证与回滚要求。

### 第 7 步：输出变更风险评估报告

报告必须包含：

```text
变更目标
影响对象
风险信号
风险等级
执行策略
需要人工确认的问题
验证要求
回滚要求
后续工作流建议
```

## 快速启动话术

```text
请参考 04-workflows/developer/change-risk-assessment-workflow.md，
基于下面的变更目标，先做变更风险评估。

变更目标：
【粘贴需求或变更说明】

请不要直接改代码，先输出影响对象、风险信号、风险等级、执行策略、需要我确认的问题、验证要求和回滚要求。
```

## 质量要求

- 必须给出风险等级和理由。
- 必须说明 AI 是否可以直接执行。
- 高风险和危险变更必须列出人工确认问题。
- 涉及数据、权限、生产配置、迁移时必须提高风险等级。
- 必须说明验证要求。
- 必须说明是否需要回滚准备。
