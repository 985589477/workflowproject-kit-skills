# 安全与权限治理工作流

## 目的

当开发任务涉及登录、鉴权、权限、用户数据、密钥、上传下载、支付、隐私、管理后台或生产配置时，帮助 AI 先识别安全和权限风险，再决定是否可以实现。

安全与权限治理不是替代专业安全审计，而是在 AI 协作开发中防止明显越权、泄露和危险操作。

## 适用场景

适用于：

- 登录、注册、鉴权、会话、token。
- 角色权限、管理员能力、付费权限。
- 用户数据、隐私数据、敏感字段。
- 文件上传、下载、导入、导出。
- 支付、订单、计费。
- 密钥、环境变量、生产配置。
- 后台管理、批量操作、删除操作。

不适用于：

- 完全不涉及权限、数据和配置的纯 UI 小改动。
- 单纯代码风格整理。

## 输入要求

- 需求或变更目标。
- 涉及用户角色。
- 涉及数据类型。
- 相关接口、页面、配置或权限点。
- 现有权限或安全规则。

## 执行原则

### 1. 默认敏感

凡是涉及用户数据、权限、支付、密钥、生产配置和删除操作，默认按高风险处理。

### 2. 最小权限

只给完成任务所需的最小权限，不扩大角色能力。

### 3. 敏感信息不入库

密钥、token、个人敏感信息、生产凭证不得写入仓库、日志、截图或示例。

### 4. 权限前后端都要检查

前端隐藏按钮不等于权限控制。必须说明服务端或接口层是否有校验。

### 5. 高风险必须确认

涉及删除、批量操作、生产数据、支付、权限放开时，必须等待用户确认。

## 执行步骤

### 第 1 步：识别安全对象

输出：

| 对象 | 是否涉及 | 说明 |
| --- | --- | --- |
| 登录鉴权 |  |  |
| 角色权限 |  |  |
| 用户数据 |  |  |
| 敏感字段 |  |  |
| 文件上传下载 |  |  |
| 支付计费 |  |  |
| 密钥配置 |  |  |
| 删除或批量操作 |  |  |

### 第 2 步：梳理权限矩阵

输出：

| 角色 | 允许操作 | 禁止操作 | 校验位置 | 待确认 |
| --- | --- | --- | --- | --- |

### 第 3 步：识别风险

检查：

- 越权访问。
- 越权修改。
- 敏感数据泄露。
- 日志泄露。
- 密钥入库。
- CSRF/XSS/注入风险。
- 上传文件类型和大小限制。
- 批量删除或不可逆操作。
- 权限缓存或状态不同步。

### 第 4 步：制定安全约束

输出：

```text
必须遵守的权限规则
必须禁止的行为
必须脱敏的数据
必须验证的接口
必须记录的审计信息
```

### 第 5 步：判断是否可实现

| 结论 | 条件 |
| --- | --- |
| 可以实现 | 风险低，权限规则清楚，验证方式明确 |
| 先确认再实现 | 权限边界、数据范围或风险不明确 |
| 不建议实现 | 存在明显泄露、越权或不可逆风险 |

## 推荐输出结构

## 快速启动话术

```text
请使用安全与权限治理工作流分析下面的开发任务。

任务：
涉及角色：
涉及数据：
相关接口或页面：

请输出安全对象、权限矩阵、敏感数据、风险清单、安全约束、验证要求和是否建议进入实现。
```

## 质量要求

- 必须识别权限和敏感数据。
- 必须说明校验位置。
- 必须列出禁止行为。
- 必须说明验证要求。
- 高风险安全变更必须要求用户确认。
