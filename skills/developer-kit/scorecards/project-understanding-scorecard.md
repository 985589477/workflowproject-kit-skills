# 已有项目理解评分表

状态: draft
版本: v1
适用对象: developer-kit 项目理解报告

## 适用场景

用于评估 AI 对已有代码项目的理解是否足够支撑后续开发。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 入口识别 | 是否检查 README、AGENTS、docs、技术栈入口和源码入口。 |
| 事实证据 | 是否用文件证据支撑判断，并区分事实、推断和待确认问题。 |
| 技术栈判断 | 是否识别语言、框架、启动、构建、测试和环境要求。 |
| 目录职责 | 是否解释主要目录职责，而不是只罗列路径。 |
| 模块地图 | 是否识别核心模块、输入输出、依赖和风险。 |
| 协作链路 | 是否说明模块之间如何协作和数据如何流动。 |
| 风险缺口 | 是否发现缺失文档、边界不清、测试缺口或高风险区域。 |
| 下一步建议 | 是否能给出明确后续工作流和进入开发前确认项。 |

总分：40 分。

## 总分判断

```text
36-40 分：可以作为后续开发上下文使用。
30-35 分：基本可用，但需要补充模块边界或风险缺口。
22-29 分：理解不足，不建议直接进入开发。
21 分及以下：需要重新阅读项目并重做理解报告。
```

## 评审输出格式

```md
# 项目理解报告评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入开发

## 后续建议
```

## 不合格信号

- 没有说明读取了哪些文件。
- 没有证据来源。
- 把推断当成事实。
- 只描述目录，不解释职责。
- 没有模块边界。
- 没有风险和缺口。
- 没有下一步建议。
- 在理解阶段直接大规模修改代码。
