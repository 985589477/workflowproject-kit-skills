# 问题定位评分表

状态: draft
版本: v1
适用对象: developer-kit 问题定位报告

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 问题输入 | 是否明确现象、环境、复现步骤、日志和最近改动。 |
| 复现判断 | 是否说明能否复现、如何复现、缺少什么信息。 |
| 事实区分 | 是否区分事实、证据、AI 推断和待确认问题。 |
| 责任域判断 | 是否判断前端、后端、数据、权限、配置、依赖等责任域。 |
| 调用链分析 | 是否说明入口、调用路径、数据来源和失败位置。 |
| 根因假设 | 是否给出有证据支撑的根因假设和验证方式。 |
| 修复策略 | 是否根据风险选择后续工作流，而不是直接乱改。 |

总分：35 分。

## 总分判断

```text
31-35 分：定位充分，可以进入修复或风险评估。
26-30 分：基本可用，需要补充复现、证据或调用链。
18-25 分：定位不足，不建议实现。
17 分及以下：需要重新定位。
```

## 评审输出格式

```md
# 问题定位评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要问题

## 必须补充的信息

## 是否建议进入修复
```

## 不合格信号

- 没有复现判断。
- 没有证据就给根因结论。
- 没有调用链。
- 没有区分事实和推断。
- 根因不清就直接建议改代码。
