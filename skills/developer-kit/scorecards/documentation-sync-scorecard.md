# 文档同步评分表

状态: draft
版本: v1
适用对象: developer-kit 文档同步报告

## 适用场景

用于评估 AI 在代码实现和验证后，是否正确判断并同步了项目文档。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 变更事实 | 是否基于真实代码变更和验证结果判断文档影响。 |
| 文档覆盖 | 是否检查 README、AGENTS、Cursor rules、docs、API、架构、模块和配置文档。 |
| 同步策略 | 是否区分不同步、小范围补充、局部改写、新增文档和待确认。 |
| 更新准确性 | 更新内容是否与代码、命令、路径、模块名和 API 保持一致。 |
| 范围控制 | 是否只更新必要文档，避免无关重写。 |
| 不确定处理 | 是否把无法确认内容标注为待确认，而不是写成事实。 |
| 未同步说明 | 是否说明未更新文档的原因和风险。 |
| 后续可用性 | 更新后的文档是否能帮助后续用户和 AI 理解项目状态。 |

总分：40 分。

## 总分判断

```text
36-40 分：文档同步充分，可以支持后续协作。
30-35 分：基本可用，但需要补充覆盖范围或一致性检查。
22-29 分：文档同步不足，可能导致后续误解。
21 分及以下：需要重新做文档同步。
```

## 评审输出格式

```md
# 文档同步评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议交付

## 后续建议
```

## 不合格信号

- 没有基于真实变更事实。
- 没有检查关键文档类型。
- 大范围重写无关文档。
- 把推断写成事实。
- 更新后的路径、命令、模块名或 API 与代码不一致。
- 没有说明未同步文档的原因。
