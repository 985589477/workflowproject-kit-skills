# 代码实现执行评分表

状态: draft
版本: v1
适用对象: developer-kit 实现交付说明

## 适用场景

用于评估 AI 完成代码实现后，变更是否受控、验证是否充分、交付说明是否清楚。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 输入承接 | 是否承接变更目标、影响范围、风险等级、模块边界和验收标准。 |
| 工作区保护 | 是否检查并保护用户已有改动，不覆盖无关变更。 |
| 规范检查 | 是否在实现前检查并遵守项目设计规范、开发规范、测试规范和 AI 协作规则。 |
| 最小必要变更 | 是否判断可复用能力、平台能力、已安装依赖和明确不做内容，避免过度设计。 |
| 范围控制 | 是否只修改必要文件，避免无关重构和风格清理。 |
| 任务拆解 | 是否把中高风险实现拆成可逐条执行、逐条验证的任务列表。 |
| 逐条执行 | 是否一次只执行一条任务，并在进入下一条前记录验证结果。 |
| 实现质量 | 是否复用现有模式，保持命名、结构和模块边界一致。 |
| 测试补充 | 是否根据影响范围补充或调整必要测试。 |
| 文档同步 | 是否同步 README、API、架构或模块文档中的必要内容。 |
| 验证结果 | 是否运行必要验证，无法运行时是否说明原因。 |
| 交付说明 | 是否清楚说明修改文件、验证结果、未验证内容、风险和后续建议。 |

总分：60 分。

## 总分判断

```text
54-60 分：实现过程受控，可以交付。
46-53 分：基本可交付，但需要补充测试、文档或说明。
36-45 分：实现存在明显缺口，需要继续修正。
35 分及以下：不建议交付，需要重新执行实现流程。
```

## 评审输出格式

```md
# 实现交付评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须修正的问题

## 是否建议交付

## 后续建议
```

## 不合格信号

- 未检查已有改动。
- 覆盖或回退用户无关改动。
- 未检查项目规范，或明显违反已有设计规范、开发规范、测试规范。
- 未做最小必要变更判断，或明显引入不必要抽象、依赖、配置和未来扩展。
- 改动明显超出影响范围。
- 中高风险任务没有任务拆解。
- 多条任务混在一起实现，无法逐条验证。
- 不遵守模块边界。
- 没有测试或验证说明。
- 验证失败但仍声称完成。
- 没有说明未验证内容和剩余风险。
