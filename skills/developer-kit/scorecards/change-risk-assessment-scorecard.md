# 变更风险评估评分表

状态: draft
版本: v1
适用对象: developer-kit 变更风险评估报告

## 适用场景

用于评估 AI 在代码修改前，对变更风险、执行策略、人工确认和验证要求的判断是否可靠。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 变更目标 | 是否说明要改什么、为什么改、影响谁、成功标准和不做范围。 |
| 影响对象 | 是否覆盖页面、模块、API、数据、状态、权限、配置、部署、测试和文档。 |
| 风险信号 | 是否识别跨模块、核心流程、数据、权限、生产配置、缺测试、批量修改和不可逆操作。 |
| 风险分级 | 是否合理判定低、中、高、危险四级，并给出理由。 |
| 执行策略 | 是否明确 AI 可以直接执行、先出方案、等待确认或默认不执行。 |
| 人工确认 | 是否列出高风险或危险变更的必须确认问题。 |
| 验证要求 | 是否说明测试、构建、手动验收和回归检查要求。 |
| 回滚要求 | 是否说明备份、回滚步骤、旧逻辑保留和不可逆风险。 |

总分：40 分。

## 总分判断

```text
36-40 分：风险评估可靠，可以作为执行策略依据。
30-35 分：基本可用，但需要补充确认点、验证或回滚要求。
22-29 分：风险判断不足，不建议进入实现。
21 分及以下：需要重新评估风险。
```

## 评审输出格式

```md
# 变更风险评估评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入实现

## 后续建议
```

## 不合格信号

- 没有风险等级。
- 没有说明 AI 是否可以直接执行。
- 涉及数据、权限或生产配置却判为低风险。
- 危险操作没有人工确认。
- 没有验证要求。
- 没有回滚要求。
- 没有下一步工作流建议。
