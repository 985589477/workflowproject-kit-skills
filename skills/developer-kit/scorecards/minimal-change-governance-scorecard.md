# 最小必要变更治理评分表

适用对象：最小变更方案、实现计划、代码评审中的过度设计检查。

## 评分维度

| 维度 | 分值 | 评分说明 |
| --- | ---: | --- |
| 需求克制 | 20 | 是否区分必须做、可选项和未来扩展 |
| 复用优先 | 20 | 是否优先查找并复用项目已有能力 |
| 低成本实现 | 20 | 是否优先使用平台、标准库或已安装依赖，避免新增依赖和抽象 |
| 完整性 | 20 | 是否没有牺牲安全、校验、错误处理、可访问性和必要测试 |
| 风险透明 | 20 | 是否说明跳过内容、剩余风险和升级条件 |

## 结论

| 分数 | 结论 |
| ---: | --- |
| 90-100 | 可进入实现，方案克制且完整 |
| 75-89 | 可试用，需要补少量风险说明 |
| 60-74 | 存在过度设计或完整性不足 |
| 0-59 | 不建议进入实现，需要重新判断方案 |
