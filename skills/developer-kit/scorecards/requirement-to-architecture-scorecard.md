# 需求到架构影响分析评分表

状态: draft
版本: v1
适用对象: developer-kit 架构影响分析报告

## 适用场景

用于评估产品需求进入开发前，AI 输出的架构影响分析是否足够支撑后续开发。

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 需求澄清 | 是否识别目标用户、场景、目标、流程、验收标准和不做范围。 |
| 影响范围 | 是否覆盖页面、组件、业务模块、状态、API、数据、权限、配置、测试和文档。 |
| 模块变更 | 是否明确哪些模块需要扩展、调整、新增、拆分或不动。 |
| 新增模块判断 | 是否基于稳定业务概念、生命周期、复用、数据模型和测试独立性判断。 |
| 数据状态分析 | 是否识别字段、实体、迁移、本地状态、全局状态、服务端状态和权限状态。 |
| 接口协作分析 | 是否识别接口、参数、返回、错误码、第三方服务和协作方。 |
| 风险分级 | 是否区分低、中、高、危险变更，并给出确认策略。 |
| 后续衔接 | 是否明确推荐下一步工作流和进入实现前确认项。 |

总分：40 分。

## 总分判断

```text
36-40 分：可以作为开发前架构影响分析使用。
30-35 分：基本可用，但需要补充影响范围或风险确认。
22-29 分：分析不足，不建议直接进入实现。
21 分及以下：需要重新做需求澄清和架构影响分析。
```

## 评审输出格式

```md
# 架构影响分析评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入实现

## 后续建议
```

## 不合格信号

- 只复述需求，没有说明项目哪里会变。
- 没有识别不清楚的问题。
- 默认新增模块，没有理由。
- 没有分析数据、状态和接口影响。
- 没有风险分级。
- 没有进入实现前的确认项。
- 没有推荐下一步工作流。
