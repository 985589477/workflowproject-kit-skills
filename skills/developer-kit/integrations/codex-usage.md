# Codex 使用说明

## 适合 Codex 的场景

Codex 更适合处理项目级开发任务，例如：

- 阅读项目结构。
- 修改多个文件。
- 运行测试或构建。
- 检查 git 状态。
- 同步文档。
- 做代码评审和风险说明。

## 推荐启动语句

```text
请使用 developer-kit 协助我处理这个开发任务：{任务}。

请先阅读：
1. developer-kit/START-HERE.md
2. developer-kit/usage-guide.md
3. developer-kit/workflows/developer/developer-kit-workflow.md

请先输出当前阶段、任务判断、风险等级、使用工作流、是否需要用户确认和下一步。
不要在完成整体功能规划前直接改代码。
```

## Codex 执行原则

- 先读项目结构，再决定改动范围。
- 保护用户已有改动。
- 使用项目现有技术栈和代码风格。
- 改代码前说明影响范围。
- 改代码后运行可用验证。
- 无法验证时说明原因。
- 最终回复必须包含修改文件、验证结果和剩余风险。

## 建议的 Codex 输出状态

```text
当前阶段：
任务判断：
使用工作流：
执行方式：
风险等级：
是否需要用户确认：
本轮会读取：
本轮可能修改：
下一步：
```

## 高风险任务处理

如果涉及以下内容，Codex 应先暂停并确认：

- 数据库迁移。
- 权限和安全逻辑。
- 支付、登录、账户、计费。
- 删除或覆盖文件。
- 大范围重构。
- 生产配置。
- 发布和回滚。

## 结束格式

```text
完成情况：
修改文件：
验证结果：
未验证内容：
风险和注意事项：
下一步建议：
```
