# 判据怎么落成代码

> 这一章解决的问题：**同一个判据，两个人写出两种口径** —— 回测能用、实盘对不上，最后谁都说自己没错。

## A. 三种典型坏形态（先认出来）

| 坏形态 | 长什么样 | 后果 |
|---|---|---|
| **内联判据** | 策略文件里直接 `if bars[-1].close > ma20 * 1.02:` | 换个策略又写一遍，阈值/口径逐渐分叉 |
| **口径无主** | 函数只有一句 docstring："判断是否放量" | 半年后没人知道是「含当天」还是「不含」、是均量 5 日还是 10 日 |
| **返回值语义混用** | 样本不足时一处返回 `None`、一处返回 `False`、一处返回 `0` | 上层 `if not x` 把"没数据"和"不成立"当同一件事，静默出错 |

## B. 登记行怎么写（口径三件套）

每个信号函数在项目口径表里占一行。格式固定，便于机器校验：

```markdown
| 判据 | 函数 | 定义式 | 量纲 | 边界 | 参数来源 |
|---|---|---|---|---|---|
```

- **判据**：人话名（与知识体系里的叫法一致，如「一字涨停」「放量倍数」「箱体突破」）。
- **函数**：`模块.函数名`（可被脚本核对是否真实存在）。
- **定义式**：以谁为基准、怎么算。**基准必须可指认**（上一根收盘 / 前 N 根不含当天 / 前高不含当根）。
- **量纲**：`%` / `倍` / `元` / `天` / `无量纲`。
- **边界**：样本不足、停牌、一字板、复权、新股、ST、缺口 —— 各自返回什么。
- **参数来源**：阈值怎么来的（"知识体系里的 1.5–3 倍" / "实测调参，上限见 docstring"），**不允许无来源的魔法数**。

## C. 三个真实样板（可直接照抄结构）

以下来自一个 Python + 日K + 回测的项目，换成你的项目时把函数名替换掉即可。注意每个函数的**边界都是显式写在代码里的**，不是靠约定。

### C1. 一字涨停

| 项 | 内容 |
|---|---|
| 判据 | 一字涨停（识别无法成交的板） |
| 函数 | `StrategyTools.is_one_price_limit_up(bars, index=-1, min_change_percent=9.8, max_range_percent=0.2)` |
| 定义式 | ① 相对**上一根收盘**的涨幅 ≥ 9.8%；② 优先认「开=高=低=收」完全相等；③ 容忍少量数据误差：若当日振幅极小且开收贴着该价，也算近似一字板 |
| 量纲 | `%` |
| 边界 | 无前收 / index 越界 → `False`；停牌（无量）→ `False`；容差 `abs_tol=1e-6` |
| 参数来源 | 9.8% 是「涨停≈10% 但受四舍五入影响」的实用阈值；0.2% 是振幅容忍度 |

> **为什么必须写清"相对上一根收盘"**：若用「当日 open 到 close」的振幅判断，除权日、跳空日会算出完全不同的结论。

### C2. 放量倍数

| 项 | 内容 |
|---|---|
| 判据 | 放量倍数（当天量相对近期均量的倍数） |
| 函数 | `StrategyTools.volume_ratio(bars, days=5, include_current=False)` |
| 定义式 | 当天成交量 ÷ 前 N 日均量；**默认分母不含当天**（`bars[-(days+1):-1]`） |
| 量纲 | `倍`（无量纲） |
| 边界 | 样本不足 N 根 → `None`；分母 ≤ 0 → `None`；要含当天必须显式 `include_current=True` |
| 参数来源 | 知识体系里的「良性放量 1.5–3 倍、>5 倍警惕出货」；`days=5` 是一周交易日 |

> **`None` 不是 0**：样本不足返回 `None` 表示"判不了"，返回 `0` 会被上层当成"完全没放量"。这条差异值得写进 docstring。

### C3. 箱体突破

| 项 | 内容 |
|---|---|
| 判据 | 箱体突破（含量能确认） |
| 函数 | `StrategyTools.box_breakout(bars, box_days=30, max_box_range_percent=20, min_breakout_percent=1.0, volume_days=5, min_volume_ratio=1.2, require_volume=True, ...)` |
| 定义式 | 最新收盘价相对**前 `box_days` 根（不含当前 K 线）**的箱体上沿，突破幅度 ≥ `min_breakout_percent`；`require_volume=True` 时还要求量比 ≥ `min_volume_ratio` |
| 量纲 | 幅度 `%`；量比 `倍` |
| 边界 | 需要 `box_days + 1` 根，不足 → 返回 `{"passed": False, "reason": "数据不足", ...}`；箱体过宽（> `max_box_range_percent`）不算有效箱体 |
| 参数来源 | 「箱体越窄，突破前震荡越充分」；1% 最小突破幅度用于排除"贴线震荡" |

> **返回 dict 而不是 bool** 是刻意的：策略要能解释"为什么没突破"（数据不足 / 幅度不够 / 量能不够），列表页也能对照 K 线展示。

## D. 写函数的 5 条要求

1. **纯函数**：不读数据库、不读全局状态、不写文件；输入 → 输出。
2. **显式参数**：阈值全部作为带默认值的参数，**不要藏在函数体里**（否则换项目/换市场就得改源码）。
3. **返回语义统一**：判"成立/不成立"用 `bool`；判"算得出/算不出"用 `T | None`；要多指标解释时返回 `dict` 且**固定字段名**。
4. **非法参数抛错**：`days <= 0` 之类直接 `raise ValueError`，不要静默返回 `None`（把编程错误当成数据不足是最难查的一类 bug）。
5. **docstring 三件套**：定义式 / 量纲 / 边界。一段话写完，不写"见上"。

## E. 参数化与前端

信号函数是后端口径的唯一来源；参数暴露给前端时：

- 参数声明（类型/最小值/最大值/默认值）必须在**后端**定义，前端只渲染控件；后端要硬校验，非法直接 400。
- 阈值变化属于**行为变化**：改了默认值，等于改了历史结论 → 必须同时更新 golden 用例，并在提交说明里写清"哪条结论变了"。
