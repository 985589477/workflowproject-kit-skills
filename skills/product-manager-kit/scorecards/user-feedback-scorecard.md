# 用户反馈整理评分表

状态: draft
版本: v1
适用对象: 产品经理用户反馈整理输出

## 适用场景

用于评审以下文件是否合格：

```text
{目标文档目录}/user-feedback-analysis.md
```

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 原话保留 | 是否保留关键用户原话和反馈来源。 |
| 分类清晰 | 是否按问题主题或场景进行清楚分类。 |
| 痛点提炼 | 是否能区分表层反馈和底层痛点。 |
| 机会识别 | 是否能形成合理需求机会，而不是直接照搬用户建议。 |
| 事实与推断 | 是否区分事实、AI 推断和待确认问题。 |
| 下游可用性 | 是否能进入需求分析、需求池或优先级判断。 |

## 总分判断

```text
26-30 分：可以进入需求分析或需求池。
21-25 分：可以进入下一阶段草稿，但必须保留待确认问题。
16-20 分：需要补充反馈来源或场景后再进入下一阶段。
15 分及以下：不建议进入下一阶段，应重新整理反馈。
```

## 评审输出格式

```md
# 用户反馈整理评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入下一阶段

## 后续建议
```

## 不合格信号

- 没有保留用户原话。
- 直接把用户建议当需求。
- 没有区分事实和推断。
- 没有反馈分类。
- 没有判断是否进入需求分析。
