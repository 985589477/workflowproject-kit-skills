# 用户故事评分表

状态: draft
版本: v1
适用对象: 产品经理用户故事输出

## 适用场景

用于评审以下文件是否合格：

```text
{目标文档目录}/user-stories.md
```

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 用户视角 | 是否从用户角色、目标和价值出发表达，而不是系统任务。 |
| 结构完整 | 是否包含“作为、我希望、以便”三要素。 |
| 来源追溯 | 是否能追溯到用户场景、功能、PRD 或产品目标。 |
| 价值清晰 | 是否能说明用户为什么需要这个能力。 |
| 可验收性 | 是否能继续生成验收标准或测试场景。 |
| 下游可用性 | 是否能被 UI 设计、开发拆解或测试继续承接。 |

## 总分判断

```text
26-30 分：可以进入验收标准、UI 设计或开发拆解。
21-25 分：可以进入下一阶段草稿，但必须补充薄弱项。
16-20 分：需要补充用户场景或功能来源后再进入下一阶段。
15 分及以下：不建议进入下一阶段，应重新生成用户故事。
```

## 评审输出格式

```md
# 用户故事评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入下一阶段

## 后续建议
```

## 不合格信号

- 用户故事只是功能名称改写。
- 缺少用户角色。
- 缺少用户价值。
- 无法追溯到功能或场景。
- 无法继续生成验收标准。
