# 优先级判断评分表

状态: draft
版本: v1
适用对象: 产品经理优先级判断输出

## 适用场景

用于评审以下文件是否合格：

```text
{目标文档目录}/priority-decision.md
```

## 评分维度

每项 1 到 5 分。

| 维度 | 评分说明 |
| --- | --- |
| 判断目标 | 是否明确本次优先级判断的目标和使用场景。 |
| 候选项清晰 | 候选项是否清楚、去重，并保留来源。 |
| 维度完整 | 是否考虑用户价值、业务价值、紧急程度、成本、风险和依赖。 |
| 依据充分 | 每个优先级结论是否有明确理由。 |
| 边界控制 | 是否明确 P0、P1、P2 和暂不做。 |
| 下游可用性 | 是否能进入版本规划、功能规划或开发排期。 |

## 总分判断

```text
26-30 分：可以进入版本规划、功能规划或开发排期。
21-25 分：可以进入下一阶段草稿，但必须补充薄弱项。
16-20 分：需要补充判断依据后再进入下一阶段。
15 分及以下：不建议进入下一阶段，应重新做优先级判断。
```

## 评审输出格式

```md
# 优先级判断评审

## 总体结论

## 分项评分

| 维度 | 分数 | 说明 |
| --- | --- | --- |

## 主要优点

## 主要问题

## 必须补充的问题

## 是否建议进入下一阶段

## 后续建议
```

## 不合格信号

- 只有排序，没有理由。
- 没有判断目标。
- 候选项来源不清楚。
- 未考虑成本、风险或依赖。
- 对信息不足事项强行排序。
- 当前版本和后续版本边界不清。
