# 快速启动示例

## 示例任务

用户输入：

```text
请使用 product-manager-kit 处理我的产品想法：
我想做一个 AI 提示词模板管理工具。
```

## AI 应该先输出什么

```text
当前阶段：任务识别
任务判断：模糊产品想法
调用能力包：product-manager-kit
使用工作流：workflows/product-manager/product-manager-workflow.md
执行方式：先做想法标准化和需求分析，暂不直接写 PRD
是否需要用户确认：需求分析后需要确认是否进入 PRD
下一步：进入想法标准化
```

## AI 不应该怎么做

不要直接输出：

```text
以下是 AI 提示词模板管理工具 PRD。
```

原因：

- 尚未确认目标用户。
- 尚未确认核心场景。
- 尚未确认产品边界。
- 尚未确认 MVP 范围。
- 尚未确认是否需要进入 PRD。

## 正确推进方式

### 第 1 步：想法标准化

AI 应先整理：

```text
产品想法：AI 提示词模板管理工具。
目标用户：待确认。
核心问题：待确认。
可能场景：AI 使用者需要管理、复用、优化提示词。
待确认问题：
1. 面向个人用户还是团队？
2. 模板是否需要分类、版本、权限？
3. 是否需要和具体 AI 工具集成？
```

### 第 2 步：需求分析

AI 应进入：

```text
requirement-analysis-workflow.md
```

输出需求目标、用户、场景、范围、非范围、风险和待确认问题。

### 第 3 步：判断是否进入 PRD

AI 应说明：

```text
当前阶段：需求分析完成
下一步建议：进入 PRD 生成
是否需要用户确认：是
原因：仍有目标用户和 MVP 范围需要确认
```

### 第 4 步：用户确认后生成 PRD

用户确认后，AI 才进入：

```text
prd-generation-workflow.md
```

### 第 5 步：PRD 后继续判断

PRD 完成后不能直接结束，必须判断：

```text
是否需要生成验收标准。
是否需要拆功能范围。
是否需要判断优先级。
是否需要做版本规划。
是否需要进入需求池。
```

## 结束条件

这个任务不能只在“PRD 写完”时结束。

至少要说明：

- 当前阶段是否完成。
- 是否存在待确认问题。
- 下一步是否进入验收标准、功能规划或版本规划。
- 如果停止，为什么停止。
- 输出是否保存为文件。
