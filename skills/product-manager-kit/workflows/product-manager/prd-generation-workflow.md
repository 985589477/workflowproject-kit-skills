# PRD 生成工作流

## 目的

把已经完成的需求分析结果转化为可被设计、开发、测试和后续项目管理承接的 PRD 初稿。

本工作流重点解决：

1. 从需求分析到 PRD 的结构化转换。
2. 控制第一版产品范围，避免 PRD 膨胀。
3. 保留待确认问题，不把 AI 推断写成确定需求。
4. 为设计、开发和测试提供可执行输入。
5. 为后续验收标准和功能规划提供稳定基础。

## 适用场景

适用于产品经理相关 PRD 生成任务，包括：

- 已完成需求分析，需要生成 PRD。
- 已明确产品边界，需要整理功能范围。
- 需要把用户场景转化为功能说明。
- 需要为开发和测试准备验收标准。
- 需要生成 MVP 版本 PRD。

如果还没有完成需求分析，应先使用：

```text
04-workflows/product-manager/requirement-analysis-workflow.md
```

## 输入要求

PRD 生成前至少需要：

- 需求分析结果。
- 产品边界。
- 目标用户。
- 使用场景。
- 产品目标。
- 第一版做与不做范围。
- 待确认问题。

推荐输入：

```text
{目标文档目录}/requirement-analysis.md
{目标文档目录}/review-gap-resolution.md
05-review/output-review.md
```

## 执行步骤

### 第 1 步：判断是否可以进入 PRD

检查需求分析是否合格、产品边界是否明确、待确认问题是否影响 PRD，并判断是否只能生成 PRD 草稿。

产出：

```text
{目标文档目录}/prd-readiness.md
```

### 第 2 步：确认产品定位和版本边界

明确产品定位、第一版范围、不做范围和后续版本内容。

产出：

```text
{目标文档目录}/prd-scope.md
```

### 第 3 步：整理用户角色和场景

提取用户角色、关键场景、用户任务路径，并区分主路径和可选路径。

产出：

```text
{目标文档目录}/prd-user-scenarios.md
```

### 第 4 步：生成功能清单

将用户场景转化为功能模块，区分核心功能和辅助功能，并排除不在第一版范围内的功能。

产出：

```text
{目标文档目录}/feature-list.md
```

### 第 5 步：编写功能说明

为每个功能写明目标、用户操作、系统行为、输入、输出和异常情况。

产出：

```text
{目标文档目录}/feature-spec.md
```

### 第 5.5 步：补充用户任务流程和交互要求

为每个核心功能明确用户入口、主要操作路径、成功条件、处理中反馈、失败恢复、取消返回和空状态。产品只描述用户行为和产品约束，不提前替 UI 决定具体颜色、字号或布局。

产出：

```text
{目标文档目录}/user-task-flows.md
```

### 第 6 步：编写验收标准

为每个核心功能生成可观察、可验证的验收标准。

产出：

```text
{目标文档目录}/acceptance-criteria.md
```

### 第 7 步：生成 PRD 初稿

按 PRD 结构整合输出，保留追溯关系、待确认问题、当前版本和后续版本。

产出：

```text
{目标文档目录}/prd.md
```

### 第 8 步：评审 PRD

检查 PRD 是否覆盖需求分析、是否越界、功能是否可执行、验收标准是否清楚、待确认问题是否保留。

产出：

```text
05-review/prd-review.md
```

## 推荐 PRD 输出结构

```md
# PRD

## 文档信息

## 背景

## 产品定位

## 目标用户

## 用户场景

## 产品目标

## 版本范围

## 功能清单

## 功能说明


## 用户任务流程与交互要求

## 验收标准

## 非功能要求

## 不做范围

## 风险与待确认问题

## 后续版本规划
```

## 质量标准

PRD 输出必须满足：

- 能追溯到需求分析结果。
- 明确第一版做什么和不做什么。
- 不把待确认问题写成确定需求。
- 功能说明能被设计和开发理解。
- 核心用户任务有清晰的入口、步骤、成功条件、反馈和恢复路径。
- 不用“简单、流畅、美观”等主观词替代可观察的交互要求。
- 验收标准能被测试或用户验证。
- 后续版本规划不干扰第一版范围。

## 常见风险

- 把需求分析重复改写成 PRD，但没有功能说明。
- 第一版范围过大。
- 功能没有来源，无法追溯。
- 验收标准太抽象。
- 忽略待确认问题。
- 把技术实现细节提前写死。
