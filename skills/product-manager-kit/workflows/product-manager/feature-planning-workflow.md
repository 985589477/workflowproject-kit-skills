# 功能规划工作流

## 目的

把产品目标、PRD、功能清单和业务约束整理成可执行的功能规划，明确当前版本先做什么、后做什么、暂不做什么。

本工作流重点解决：

1. 将 PRD 中的功能描述转成结构化功能模块。
2. 区分 P0、P1、P2 和暂不做。
3. 明确版本目标和功能边界。
4. 标记功能依赖、风险和待确认问题。
5. 为 UI 设计、开发任务拆解和版本规划提供上游输入。

## 适用场景

适用于产品经理相关功能规划任务，包括：

- 已完成 PRD，需要拆成功能规划。
- 已有功能清单，需要判断优先级。
- 准备进入 UI 设计或开发拆解前，需要明确当前版本范围。
- 需要把产品目标拆成模块和阶段。

如果还没有 PRD，应先使用：

```text
04-workflows/product-manager/prd-generation-workflow.md
```

## 输入要求

至少需要以下一种输入：

- PRD。
- 功能清单。
- 产品目标。
- 业务约束。
- 版本范围。

推荐输入：

```text
{目标文档目录}/prd.md
{目标文档目录}/feature-list.md
{目标文档目录}/prd-scope.md
{目标文档目录}/feature-spec.md
```

## 执行步骤

### 第 1 步：确认版本目标

- 提取当前版本目标。
- 明确产品要优先解决的问题。
- 标记不属于当前版本的目标。

产出：`{目标文档目录}/version-goal.md`

### 第 2 步：提取功能候选池

- 从 PRD、功能清单和功能说明中提取候选功能。
- 保留来源和对应用户场景。
- 合并重复功能。

产出：`{目标文档目录}/feature-candidate-pool.md`

### 第 3 步：划分功能模块

- 按用户任务或产品结构分组。
- 识别核心模块、辅助模块和后续模块。
- 标记模块之间的依赖。

产出：`{目标文档目录}/feature-modules.md`

### 第 4 步：判断功能优先级

- 根据版本目标、用户价值、依赖关系和实现风险判断优先级。
- 区分 P0、P1、P2 和暂不做。
- 对不确定优先级写入待确认。

产出：`{目标文档目录}/feature-priority.md`

### 第 5 步：输出功能规划

- 整合版本目标、功能模块、优先级、依赖和风险。
- 明确当前版本包含与不包含的功能。

产出：`{目标文档目录}/feature-planning.md`

### 第 6 步：评审功能规划

- 检查是否符合版本目标。
- 检查是否越界。
- 检查优先级是否有依据。
- 检查是否能被 UI 和开发承接。

产出：`05-review/feature-planning-review.md`

## 推荐输出结构

```md
# 功能规划

## 版本目标

## 功能模块总览

| 模块 | 功能 | 优先级 | 当前版本是否包含 | 来源 | 说明 |
| --- | --- | --- | --- | --- | --- |

## P0 功能

## P1 功能

## P2 功能

## 暂不做范围

## 依赖关系

## 风险与待确认问题

## 后续版本建议
```

## 质量标准

- 功能规划能追溯到 PRD 或产品目标。
- 当前版本范围清楚。
- P0、P1、P2 和暂不做区分明确。
- 优先级判断有依据。
- 功能依赖和风险被标记。
- 能被 UI 设计、开发拆解或版本规划继续承接。
